# Schema Teams Desktop — правила для Claude Code

Настольное приложение Schema Teams для Windows: трей, уведомления, быстрый ответ, открытие путей `\\сервер\…`, таймер учёта времени. Источник истины — ТЗ `docs/tz/README.md`, эталон вида и поведения — `docs/mockups/Schema Teams Desktop — макет_v1.html`.

## Главные правила

1. ТЗ — источник истины. Задача расходится с ТЗ или ТЗ неясно — остановиться и спросить руководителя бюро. Не придумывать. Решения сверх ТЗ — строкой в `docs/decisions.md`.
2. Работаем по шагам Д1 → Д6 (ТЗ, раздел 12). Не делать работу следующего шага.
3. **Репозиторий открытый — его видят все.** Реальные данные бюро в него не попадают: фамилии, имена, логины, объекты, заказчики, адреса серверов, IP, порты, пути, пароли, ключи, сертификаты (`.pfx`, `.cer`), `.env`. В тестах и примерах — только вымышленные «Иванова И.И.», «Объект А», `<SERVER_HOST>`, `\\server\…`. Перед коммитом — `./scripts/check-private-data.sh`.
4. Безопасность — в каждом шаге (ТЗ, 2.4): `contextIsolation`, `sandbox`, мост только для адреса сервера, никаких произвольных команд.
5. Прямо в `main` не отправлять: работа — в ветке, слияние — через pull request и только при зелёной проверке.

## Правила кода

- TypeScript `strict`; `any` — только с комментарием, почему.
- Приложение — тонкая оболочка (ТЗ, 2.2): вызовы API делает страница Teams через мост, у приложения нет пароля, токена и CSRF-ключа.
- Договор моста — `src/bridge/protocol.ts`, копия `packages/shared/src/desktop-bridge.ts` из `schema-teams`; меняется только вместе, с номером версии протокола.
- Тексты интерфейса — в файле строк, формулировки как в макете и ТЗ.
- Зависимости — только MIT, Apache-2.0, BSD-2/3-Clause, ISC, 0BSD; проверить до добавления. Исключение — `ffmpeg.dll` в поставке Electron (`docs/decisions.md`).
- Журнал приложения не содержит текстов сообщений, паролей и cookie.

## Тесты

- Логика главного процесса (правила путей, округление, очередь команд, версии) — модульные тесты Vitest.
- Сквозные — Playwright `_electron` против заглушки сервера.
- Нельзя удалять или отключать тесты и проверки, чтобы сборка прошла.

## Команды

- `npm install` — зависимости (Node 22.12+). Сам Electron скачивается при первом запуске.
- `npm start` — сборка и запуск. Адрес сервера — `SCHEMA_TEAMS_SERVER_URL` (например, локальный стенд `schema-teams`), иначе из `settings.json` или `.env`.
- `npm test` — модульные тесты; `npm run test:e2e` — сквозные (Playwright `_electron`, заглушка сервера `tests/e2e/stub.ts`).
- `npm run typecheck`, `npm run lint` (ESLint и Prettier), `npm run format`.
- `npm run check` — всё перед PR: типы, линт, модульные и сквозные тесты.
- `npm run dist` — установщик `release/Schema Teams Setup <версия>.exe`; адрес сервера — из `SERVER_URL` или `.env`.
- Тихая установка для проверки — установщик с ключом `/S`; удаление — `%LOCALAPPDATA%\Programs\Schema Teams\Uninstall Schema Teams.exe /S`.

Переменные для разработки и тестов: `SCHEMA_TEAMS_SERVER_URL` — адрес сервера, `SCHEMA_TEAMS_USER_DATA` — отдельная папка профиля (настройки, cookie, журнал).

## Устройство

- `src/main/index.ts` — запуск: один экземпляр, журнал, разрешения, автозапуск, окно, трей.
- `mainWindow.ts` — окно Teams: переходы только в пределах сервера, ✕ и «Свернуть» — в трей, страница «Нет связи» с повтором, масштаб, положение окна.
- `tray.ts`, `icons.ts`, `mark.ts`, `png.ts` — значок: знак Schema рисуется на лету.
- `navigation.ts`, `windowState.ts`, `settings.ts`, `logger.ts`, `config.ts` — логика без Electron, покрыта модульными тестами.
- `strings.ts` — тексты интерфейса.
