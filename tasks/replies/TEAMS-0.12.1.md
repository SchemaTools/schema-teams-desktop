## 2. Утренняя сводка — [Предложение] принято

`GET /api/desktop/morning` (любой вошедший):

```json
{ "date": "2026-10-30", "workday": true, "dueToday": 2, "review": 3, "newRemarks": 4 }
```

- `date` — сегодня по часовому поясу бюро; `workday` — по производственному календарю.
- `dueToday` — мои альбомы и подзадачи (я исполнитель) со сроком сегодня, кроме выданных и отменённых.
- `review` — как «Ждут моей проверки» на «Моей странице»; без права `review` — 0.
- `newRemarks` — замечания от других людей, созданные после конца прошлого рабочего дня (последний рабочий день по
  календарю, `workEnd` бюро в его поясе), не отменённые, где я исполнитель замечания или исполнитель альбома / его подзадачи.
- Видимость и «без архивных объектов» — как в «Моих задачах». Ссылку сервер не отдаёт (у приложения — `/my`).

## 3. «Сообщить о проблеме» — [Предложение] изменено: два шага

На сервере нет разбора multipart; вместо новой зависимости файлы грузятся так же, как вложения чата.

1. `POST /api/desktop/support/files` — тело — байты файла, `Content-Type: application/octet-stream`, имя — заголовок
   `X-File-Name` (encodeURIComponent); до 50 МБ, тип проверяется по содержимому, исполняемые нельзя (400) →
   201 `ChatFile`:

   ```json
   { "fileId": 41, "fileName": "logs.zip", "size": 1834, "mime": "application/zip", "isImage": false }
   ```

2. `POST /api/desktop/support` (CSRF; `Idempotency-Key` — как у сообщений чата, необязателен):

   ```json
   { "text": "Плагин не запускается", "fileIds": [40, 41] }
   ```
   → 201 `{ "chatId": 12, "messageId": 815 }`; повтор с тем же ключом — 200 с тем же `messageId`; ключ, занятый
   сообщением другого разговора, — 409 `idempotency_conflict`.

- Сообщение — в чат поддержки **от имени отправителя, в участники он не добавляется** (разговор у него не появляется);
  ответ поддержки — в личные (решение Д2 от 29.10). Участники чата поддержки получают обычный `chat:message`.
- До 3 файлов (`DESKTOP_SUPPORT_FILES_MAX`); приложить можно только свои загруженные и ещё не отправленные. Пустой
  текст — только с файлами. Упоминания в тексте не разбираются.
- Чат поддержки не выбран — **409** на обоих маршрутах:

  ```json
  { "error": { "code": "no_support_chat", "message": "Чат поддержки не выбран" } }
  ```
  Приложение узнаёт заранее по `GET /api/desktop/config` → `supportChatId: null`.
- Журнал безопасности — факт обращения (кто, когда, номера сообщения и файлов), без текста и имён файлов.
- Чат поддержки выбирает администратор: «Администрирование → Бюро и оформление → Чат поддержки» — групповой разговор,
  где администратор участвует.

## 4. Реестр плагинов Revit — [Решение 25.10] выполнено, [Предложение] принято с дополнениями

### Для приложения (любой вошедший)

`GET /api/desktop/plugins` (испытатель):

```json
{
  "tester": true,
  "plugins": [
    {
      "code": "floor-plans", "name": "Планы этажей", "short": "ПЭ",
      "stable": {
        "id": 3, "version": "1.4.1", "verified": true, "revit": [2025, 2026], "notes": "Оси с изломами",
        "size": 605112, "sha256": "9f2c…(64 знака)", "url": "/api/desktop/plugins/files/3",
        "publishedAt": "2026-10-30T02:41:00.000Z",
        "requires": [{ "plugin": "schema-tools", "minVersion": "2.0" }]
      },
      "beta": {
        "id": 5, "version": "1.5", "verified": false, "revit": [2026], "notes": "",
        "size": 154020, "sha256": "…", "url": "/api/desktop/plugins/files/5",
        "publishedAt": "2026-10-30T02:41:00.000Z", "requires": []
      }
    }
  ]
}
```

- `stable` — последняя проверенная рабочая (по номеру версии: 1.10 новее 1.9; при равенстве — по времени загрузки);
  отозвали — в `stable` предыдущая проверенная. `beta` — последняя пробная, **только испытателю** (раздаётся без
  отметки «проверена»); неиспытателю всегда `null`.
- `GET /api/desktop/plugins/files/:id` — zip сборки; отдаёт любую не отозванную проверенную рабочую сборку (не только
  последнюю — чтобы приложение могло поставить версию по зависимости) и пробную испытателю. Пробная неиспытателю,
  отозванная, снятый плагин — 404. `sha256` и `size` считает сервер при приёме — приложение сверяет скачанное.
- Событие Socket.IO **`desktop:plugins`** (без данных) всем вошедшим — после **каждого** изменения реестра (новая
  сборка, «проверена», отзыв, перевод канала, «Что нового», снятие плагина, испытатели): перечитать список.
- Подпись `.dll` сервер не проверяет — это делает приложение. При загрузке сервер проверяет только zip: есть `.addin`
  и `.dll`, нет путей вне папки (`..`, абсолютных, с буквой диска).

### Управление (право `plugins_manage` — администратор и BIM-менеджер)

`GET` / `POST /api/admin/plugins`, `PATCH /api/admin/plugins/:code` `{name?, short?, order?, retired?}`,
`POST /api/admin/plugins/:code/builds?version=&channel=&revit=2025,2026&requires=код:версия,…` (тело — байты zip,
имя — `X-File-Name`; до 200 МБ, больше — 413; повтор версии в плагине и канале — 409),
`PATCH /api/admin/plugins/builds/:id` `{verified?, channel?, notes?, revoked?, requires?}`,
`GET` / `PUT /api/admin/plugins/testers` `{userIds}`. Без права — 403. Каждое действие — в журнал безопасности.
Страница сайта — «Администрирование → Плагины Revit» (`/admin?t=plugins`).

### Дополнения к предложению

| Что | Почему |
|---|---|
| `requires` — параметром загрузки и полем `PATCH …/builds/:id` | в предложении было только в ответе |
| «проверена» и отзыв можно снять (`verified: false`, `revoked: false`) | ошибочная отметка исправляется, с записью в журнал |
| `desktop:plugins` после любого изменения, а не только проверки, отзыва и испытателей | новая пробная, перевод канала, снятие тоже меняют то, что видит приложение |
| `files/:id` отдаёт и прежние проверенные рабочие | установка версии по зависимости |
| Файлы — отдельный том `plugins`, не в резервной копии | сборку можно загрузить заново; строки реестра копируются |

## 6. Оставшиеся ограничения

- Перенос сборок из прежней папки на сервере — вручную через страницу «Плагины Revit» (последняя рабочая каждого
  плагина с отметкой «проверена»); пока реестр пуст, `GET /api/desktop/plugins` отдаёт плагины без сборок или пустой список.
- Пакетной загрузки нет — одна сборка за запрос.
- Сервер не проверяет подпись `.dll` и совместимость с версией Revit сверх списка `revit` — это делает приложение.
- «Сообщить о проблеме» требует выбранного чата поддержки; без него — 409, приложение показывает свой запасной путь.
- Утренняя сводка не отдаёт ссылку и списки задач — только числа.
