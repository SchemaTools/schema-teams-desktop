## 2. Что сделано и изменённые общие типы

### Ч1. Реакции 🔥 и 🎉 — [Предложение] принято как есть

`packages/shared/src/chat.ts`: `CHAT_REACTIONS` = `like, done, look, heart, laugh, question, fire, party` —
`fire` 🔥 и `party` 🎉 в конце, прежние не убраны. Сайт показывает все восемь. `chat:reaction` — как прежде:
`{chatId, messageId, reactions: ChatReaction[]}`. Ставится `POST /api/chats/:id/messages/:mid/reactions {kind}`,
снимается `DELETE /api/chats/:id/messages/:mid/reactions/:kind`.

### Ч2. «Мои задачи на объекте» — [Предложение] принято, уточнено

`ChatSummary.myActiveTasks: number` — у чата объекта число моих незавершённых альбомов и подзадач объекта
(я исполнитель, правило видимости, объект не в архиве, без выданных и снятых), у прочих — 0.
`packages/shared/src/employee.ts`: `MyTaskRow.objectId: number`.
`chat:list` (без данных) приходит при назначении, выдаче, снятии, удалении, восстановлении задачи и смене
исполнителя — прежним и новым исполнителям. Смена статуса внутри работы (`in_progress`, `review`…) события не даёт.

### Ч3. Закрепление чата — [Предложение] принято

`PUT /api/chats/:id/top` `{"top": true|false}` → `ChatSummary`; поле `ChatSummary.top: boolean`; `CHAT_TOP_MAX = 5`,
`chatTopInput`. Закрепление своё, у коллег порядок не меняется. Закреплённые — вверху списка (между собой —
по последнему сообщению). Повтор — 200 без изменений. `chat:list` — только себе.

```json
{
  "id": 12, "kind": "object", "title": "01/2026-01 · Объект А", "peer": null, "objectId": 3,
  "memberCount": 6, "last": null, "unread": 0, "mentioned": false, "photoFileId": null,
  "peerAvatar": null, "objectCode": "01/2026-01",
  "myActiveTasks": 2,
  "top": true
}
```

Шестой закреплённый — 409:

```json
{ "error": { "code": "top_limit", "message": "Закрепить можно не больше 5 чатов" } }
```

### Ч4. «Альбом выдан» и «Все замечания закрыты» — [Предложение] принято, уточнено

`packages/shared/src/notifications.ts`: `NOTIFICATION_EVENTS` += `album_issued`, `remarks_closed`;
`packages/shared/src/notification-settings.ts` — строки «Альбом выдан», «Все замечания закрыты», по умолчанию включены.

- `album_issued` — исполнителям альбома, исполнителям его подзадач и проверяющему (кроме автора изменения),
  один раз на выдачу; повторная выдача после возврата — новое событие.
- `remarks_closed` — исполнителям альбома, когда закрыто или снято последнее открытое замечание (и хотя бы одно закрыто).
- `link` — карточка альбома `/albums/:id`. Выключено в настройках — не создаётся.
- В событии `notification` — `kind` (= `item.event`) и, с PR-5, `notificationId` (= `item.id`):

```json
{
  "item": { "id": 501, "event": "album_issued", "at": "2026-10-30T09:12:00.000Z", "read": false,
            "author": { "id": 4, "shortName": "Сотрудник А.А.", "photoFileId": null, "avatar": "male" },
            "task": { "id": 77, "kind": "album", "mark": "АР", "title": "Архитектурные решения",
                      "objectName": "Объект А", "stageCode": "П" },
            "changes": [{ "field": "status", "from": "На проверке", "to": "Выдан" }],
            "reason": null, "subject": null, "link": "/albums/77" },
  "kind": "album_issued",
  "notificationId": 501,
  "quiet": false
}
```

(Фамилии и объекты в примерах — условные.)

### Признак тишины `quiet` в `chat:message` (постановка 3.1, решение Д3 от 29.10)

Событие `chat:message` получателю — тип `ChatMessageEvent` = `ChatMessage` + `quiet: boolean`, считается для каждого
получателя при отправке:

- тихие часы получателя (настройка уведомлений «все события», по часовому поясу бюро) → `true`, в том числе для
  упоминания (как у плашек уведомлений сайта);
- включённый «Фокус» → `true`, кроме сообщения с упоминанием этого получателя;
- иначе `false`.

Ответ отправителю на `POST /api/chats/:id/messages`, лента и `chat:update` поля не несут; сообщение и счётчики не меняются.

```json
{ "id": 812, "chatId": 5, "author": { "id": 7, "shortName": "Сотрудник Б.Б." }, "text": "Добрый вечер",
  "files": [], "reactions": [], "canEdit": false, "...": "…остальные поля ChatMessage…", "quiet": true }
```

### `GET /api/desktop/config` (постановка 3.2) и чат поддержки (3.3)

`packages/shared/src/desktop-config.ts` — `DesktopConfig`, `DesktopCapabilities`. Любой вошедший:

```json
{ "bureau": { "timeZone": "Europe/Moscow", "workEnd": "18:00" },
  "serverNow": "2026-10-30T07:00:00.000Z",
  "supportChatId": 12,
  "capabilities": { "chatQuiet": 1, "morning": 1, "support": 1, "plugins": 1, "timerControl": 2 } }
```

- `capabilities`: число — версия договора функции, нет поля — функции нет. Объявляются только влитые и проверенные.
  В 0.12.1 — все пять, как в примере.
- `supportChatId` — групповой разговор, выбранный администратором («Администрирование → Бюро и оформление →
  Чат поддержки»), или `null`. «Сообщить о проблеме» — см. `TEAMS-0.12.1.md`.

## 5. Оставшиеся ограничения

- Готовность сервера ≠ готовность чата: интеграция и ручная приёмка по ТЗ Desktop v4 (сценарии 7–9, 25–28) — на стороне Desktop.
- Ч5 «без звука» нет: серого счётчика по данным сервера не будет.
- `quiet` есть только в событии сокета; при загрузке ленты после переподключения признака нет — тишину
  на этот момент Desktop может оценить сам по `GET /api/desktop/config` и своим настройкам, либо не показывать
  всплывающие уведомления для догруженных сообщений.
- `chat:list` для Ч2 рассылается разборщиком журнала после фиксации транзакции — с задержкой разборщика
  (доли секунды — секунды), не мгновенно.
- Однофамилец с теми же инициалами в бюро может получить лишний `chat:list` — безвредно (перечитать список).
- Мост `desktop-bridge.ts` остаётся 1.1 (blob `21bb1258ab9f82b05786e1ba11f58f7ec4fa56f6`, без изменений).
