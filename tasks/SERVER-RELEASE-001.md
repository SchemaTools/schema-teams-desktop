# SERVER-RELEASE-001 — сервер Schema Teams под выпуск Desktop 1.0

Дата: 05.11.2026. Статус: **постановка, не выполнена**.
Исполнитель — ответственный за сервер Schema Teams (репозиторий `SchemaTools/schema-teams`).
Desktop-код исполнитель не меняет. Основание: решения руководителя 05.11 — Desktop 1.0
влит в `main` целиком (`75b937b`), подпись — сертификатом плагинов бюро, ручные проверки
Desktop — в работе в бюро.

## 0. Коротко

Код сервера для приложения почти готов: в `stage/e13` (`9fa9de8`, 05.11) уже есть всё,
на что опирается Desktop 1.0. Осталось:

1. **Выпустить** `stage/e13` на сервер бюро (раздел 1).
2. **Доделать два небольших договора** — откат плагина и повтор загрузки диагностики (раздел 2).
3. **Настроить сервер бюро** под приложение: чат поддержки, реестр плагинов, стикеры,
   раздача установщика Desktop (раздел 3).

## 1. Выпуск

- Влить `stage/e13` и выпустить версию сервера (номер — по правилам Teams), поставить на
  сервер бюро по `deploy/README.md`, с резервной копией до обновления.
- **Проверка после выпуска** (с компьютера бюро, вход сотрудником):
  - `GET /api/health` — `status: ok`, версия не ниже **0.11.0** (минимум Desktop,
    `MINIMUM_SERVER_VERSION`);
  - `GET /api/desktop/config` — `capabilities`: `timerControl` **≥ 2**, `plugins` **≥ 1**,
    `support` **≥ 1**; `bureau.timeZone`, `bureau.workEnd` заполнены; `supportChatId` —
    не `null` (после раздела 3);
  - `GET /api/desktop/latest` отвечает (после раздела 3.4);
  - события сокета для Desktop доходят: `chat:message`, `chat:list`, `chat:read`,
    `chat:reaction`, `chat:stickers`, `chat:pin`, `notification` (с `quiet`), `focus`,
    `time:timer`, `desktop:plugins`, `session`.
- Что уже есть в `stage/e13` и **менять не нужно** (сверено 05.11 по коду): реестр
  плагинов (`/api/admin/plugins`, испытатели `/api/admin/plugins/testers`, каталог
  `/api/desktop/plugins`, файлы `/api/desktop/plugins/files/:id`); `/api/desktop/config`,
  `/latest`, `/files/:name`, `/morning`, `/support`, `/timer-notices/pending` и `/ack`;
  закрепление чата (`/api/chats/:id/top`), «мои задачи на объекте» (`myActiveTasks`),
  реакции 🔥 и 🎉, события `album_issued` и `remarks_closed`, стикеры и эмодзи бюро
  (`/api/chat-stickers`), вложения для панели сведений (`/api/chats/:id/attachments`),
  фото профиля (`/api/profile`, `/api/files/:id`).

## 2. Доделать

### 2.1. SERVER-PLUGINS-001 — сведения об известной сборке для отката — **нужно для 1.0**

[SERVER-PLUGINS-001](SERVER-PLUGINS-001.md). Read-only `GET /api/desktop/plugins/builds/:id`
для одного известного ID: актуальные `tester`, `pluginCode`, `build {id, version, channel,
verified, revit, requires, notes, size, sha256, url, publishedAt}` из одного согласованного
чтения; доступ не слабее file GET (revoked, retired, неподтверждённая stable, beta без
tester → 404). После готовности — `capabilities.plugins = 2`; каталог и file GET версии 1 —
без изменений.

Зачем: без маршрута «Вернуть прошлую версию» (сценарий 14 ТЗ Desktop) при неоднозначности
блокируется — приложение не угадывает канал и зависимости старой сборки.

### 2.2. SERVER-CHAT-001, дополнение 31.10 — повтор загрузки диагностики — **желательно**

[SERVER-CHAT-001](SERVER-CHAT-001.md), раздел «Дополнение от 31.10.2026».
`POST /api/desktop/support/files` сделать идемпотентным по ключу повтора (как `support` и
отправка сообщения): повтор после потери ответа не создаёт вторую запись файла. После
готовности — `capabilities.support = 2`; клиент с `support: 1` продолжает работать.

Зачем: при обрыве связи «Сообщить о проблеме» может оставить на сервере лишние
неотправленные файлы.

### 2.3. Не нужно для 1.0

Чат «без звука» (ТЗ Desktop 5.2 п. 5 — «если появится»).

## 3. Настроить на сервере бюро

### 3.1. Чат поддержки

Назначить чат поддержки бюро (`supportChatId` в настройках бюро) — туда приходят обращения
«Сообщить о проблеме» со снимком и журналами. Без него приложение только сохраняет архив у
сотрудника.

### 3.2. Реестр плагинов (ведут администратор и BIM-менеджер)

- Загрузить текущие сборки плагинов Revit в реестр. Сборки **подписаны сертификатом бюро
  «Schema Bureau Revit Plugins»**: приложение ставит только файлы с этой подписью —
  отпечаток SHA-256 зашит в Desktop 1.0 (`BUREAU_PUBLISHER_DER_SHA256`).
- Отметить проверенные сборки (`verified`) — автоматически ставятся только они.
- Назначить испытателей пробных сборок.

### 3.3. Стикеры и эмодзи бюро

Загрузить стартовый набор (команда `import-stickers` или вручную). Desktop 1.0 показывает
стикеры и эмодзи бюро (`:код:`) и сам набор не пополняет — это на сайте.

### 3.4. Раздача установщика Desktop

- Положить в `data/desktop/` подписанный установщик `Schema Teams Setup <версия>.exe` и
  `latest.json` `{version, notes, file, sha256, size}` — как описано в
  `apps/server/src/modules/desktop/routes.ts`. Установщик собирается в Desktop командой
  `npm run dist:signed` на компьютере, где лежит сертификат бюро с ключом.
- Обновление приложения ставит только установщик, подписанный тем же сертификатом, что и
  установленное приложение.
- Если раздачу удобнее вести из админки (загрузка файла вместо ручного `latest.json`) —
  предложить отдельным пунктом; для 1.0 достаточно файлов.

- Репозиторий Desktop открытый: в эту ветку — без адресов серверов, логинов, паролей,
