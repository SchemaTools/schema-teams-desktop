# Постановка для Schema Teams: что нужно настольному приложению 1.0

Дата: 2026-10-25 · Основание: ТЗ Schema Teams Desktop 1.0 v4 (разделы 3.4, 8.2, 8.5, 5.5, 6, 13), сверка API — `docs/server-api.md` репозитория `schema-teams-desktop` · Номер версии Teams — по плану Teams · Документ обезличен.

**Зачем.** С ТЗ v4 настольное приложение — свой клиент: само держит Socket.IO и вызывает API сервера по cookie сессии (мост со страницей больше не нужен). Чат сервер уже даёт почти весь (0.8.0–0.11.0). Не хватает реестра плагинов Revit и нескольких мелочей для окна приложения. Пометки: **[Решение]** — решение руководителя бюро, не менять; **[Предложение Claude]** — можно менять с записью в `docs/decisions.md` Teams.

## 1. Реестр плагинов Revit

**[Решение]** Сборки плагинов бюро хранятся в Teams, а не в папке на сервере, куда их выкладывают сейчас. Загружают сборки, ставят «проверена» и ведут список испытателей **администратор и BIM-менеджер**. Приложение ставит само только проверенные сборки; пробные — только испытателям с включённым переключателем «Пробные».

Устройство — **[Предложение Claude]**.

### 1.1. Право и данные

- Новое право `plugins_manage` — у ролей «Администратор» и «BIM-менеджер».
- **Плагин:** код (латиница, `floor-plans`), название («Планы этажей»), сокращение для значка (2–3 знака), порядок, «снят» (больше не раздаётся).
- **Сборка:** плагин, версия `X.Y` или `X.Y.Z`, канал `stable` (рабочая) / `beta` (пробная), «проверена» (кто и когда), версии Revit (`[2025, 2026]`), «Что нового» (текст до 10 000 знаков), файл, размер, `sha256` (считает сервер), зависимости `[{plugin, minVersion}]` (например, общая библиотека), кто загрузил и когда, «отозвана».
- **Испытатели:** список сотрудников; испытатель видит пробные сборки.
- Файлы — в отдельной папке тома данных (как `data/desktop/`), не среди вложений задач: в архиве сборки — `.dll`, которые в чат и задачи прикладывать нельзя.

### 1.2. Маршруты для приложения (любой вошедший)

```
GET /api/desktop/plugins
→ {
    tester: boolean,                      // я — испытатель
    plugins: [{
      code, name, short,
      stable: Build | null,               // последняя проверенная рабочая
      beta:   Build | null                // последняя пробная — только испытателю, иначе null
    }]
  }
Build = { id, version, verified: boolean, revit: number[], notes, size, sha256,
          url: "/api/desktop/plugins/files/<id>", publishedAt, requires: [{plugin, minVersion}] }

GET /api/desktop/plugins/files/:id        файл сборки (zip), только раздаваемой этому пользователю
```

- Неиспытателю пробные сборки не отдаются ни в списке, ни по `files/:id` (404).
- Отозванная сборка не раздаётся; если рабочую отозвали — в `stable` предыдущая проверенная.
- Событие сокета `desktop:plugins` (без данных) всем вошедшим — когда сборку проверили, отозвали или изменился список испытателей: приложение проверяет обновления сразу, не дожидаясь 6 часов.
- Подписи `.dll` сервер не проверяет — это делает приложение (ТЗ 8.3). **[Предложение Claude]** при загрузке сервер проверяет только, что это zip с `.addin` и `.dll` внутри.

### 1.3. Маршруты для управления (право `plugins_manage`)

```
GET    /api/admin/plugins                         плагины со всеми сборками
POST   /api/admin/plugins                         {code, name, short} → плагин
PATCH  /api/admin/plugins/:code                   {name?, short?, order?, retired?}
POST   /api/admin/plugins/:code/builds?version=&channel=&revit=2025,2026
                                                   тело — байты zip, имя — X-File-Name → сборка
PATCH  /api/admin/plugins/builds/:id              {verified?, channel?, notes?, revoked?}
GET    /api/admin/plugins/testers                 → PersonRef[]
PUT    /api/admin/plugins/testers                 {userIds: number[]}
```

- Предел файла — 200 МБ (сборки бывают крупнее 50 МБ вложений).
- Повтор версии в том же плагине и канале — 409.
- Каждое действие — в журнал безопасности (загрузил, проверил, отозвал, изменил испытателей).
- Страница «Плагины Revit» в разделе администрирования сайта: список плагинов и сборок, загрузка, «Проверена ✓», «Отозвать», испытатели.

### 1.4. Перенос

Сборки из нынешней папки на сервере администратор или BIM-менеджер загружают в реестр вручную (последняя рабочая каждого плагина, отметка «проверена»). Папку приложение не читает.

## 2. Реакции 🔥 и 🎉

ТЗ приложения 2.5: панель быстрых реакций 👍 ❤️ 🔥 ✅ 👀 🎉. На сервере набор `like 👍, done ✅, look 👀, heart ❤️, laugh 😂, question ❓` (`CHAT_REACTIONS`).

**[Решение 25.10]** Добавить 🔥 и 🎉 в набор сервера. **[Предложение Claude]** по устройству: в конец `CHAT_REACTIONS` — `fire` 🔥 и `party` 🎉, ничего не убирая (поставленные реакции не теряются); сайт показывает все восемь.

## 3. «У меня есть задачи на объекте» в списке чатов

Приложение делит список чатов на цветные группы: «<Объект> · в работе» — чаты объектов, где у пользователя есть активные задачи. **[Решение 25.10]** Чатов отдельных задач не будет — только чаты объектов, личные, групповые и общий чат бюро; новых видов разговоров постановка не требует. В `ChatSummary` есть `objectId`, а в «Моей странице» (`MyTaskRow`) — только название объекта.

**[Предложение Claude]** В `ChatSummary` поле `myActiveTasks: number` — у чата объекта число моих незавершённых альбомов и подзадач на этом объекте (те же, что в «Моих задачах», кроме выданных и снятых); у прочих чатов — 0. Изменилось (назначили, выдали) — событие `chat:list` этому пользователю. Дополнительно — `objectId` в `MyTaskRow`.

## 4. Утренняя сводка одним маршрутом

ТЗ приложения 5.5: одно уведомление в начале рабочего дня — «Сроки сегодня: 2 · На проверке: 3 · Новых замечаний: 4». Сейчас «Новых замечаний» взять неоткуда, остальное — три запроса.

**[Предложение Claude]**

```
GET /api/desktop/morning
→ { date: "ГГГГ-ММ-ДД",          // сегодня по часовому поясу бюро
    workday: boolean,            // рабочий день по производственному календарю
    dueToday: number,            // мои незавершённые альбомы и подзадачи со сроком сегодня
    review: number,              // ждут моей проверки (право review), иначе 0
    newRemarks: number }         // замечания к моим альбомам, созданные после конца прошлого рабочего дня
```

Ссылка «Открыть ↗» — «Моя страница» (`/my`).

## 5. Чат поддержки для «Сообщить о проблеме»

ТЗ приложения 13: снимок экрана, описание и архив журналов (приложения, плагинов, Revit) уходят одним сообщением в чат поддержки Teams. Настройки «чат поддержки» на сервере нет; обратная связь (`/api/feedback`) принимает только текст и одну картинку.

**[Предложение Claude]**

- В настройках бюро — «Чат поддержки»: выбор группового разговора (обычно — администратор и BIM-менеджер).
- `GET /api/desktop/config` (любой вошедший) → `{supportChatId: number | null}`; если отправитель не участник этого чата — сервер добавляет его при первом обращении, либо `POST /api/desktop/support` принимает сообщение с файлами от любого вошедшего и публикует в чат поддержки от его имени. Выбор — за Teams.
- Нет настройки — приложение открывает форму обратной связи сайта и папку с собранным архивом (это уже работает без изменений сервера).

## 6. Закрепление чата в списке

ТЗ приложения 6.1: булавка у закреплённого чата, по наведению «Закрепить». Сейчас закрепляется только сообщение внутри чата.

**[Предложение Claude]** Своё для каждого пользователя: `PUT /api/chats/:id/top {top: boolean}`, в `ChatSummary` — `top: boolean`; закреплённые — вверху списка, до 5 штук; событие `chat:list` себе. Сайт может показывать так же.

## 7. События «Альбом выдан» и «Все замечания закрыты»

ТЗ приложения 6.2: служебный чат «Schema Teams» показывает события колокольчика карточками; «Альбом выдан» — с праздником. Сейчас при выдаче альбома исполнитель уведомления не получает (`subtasks_done` — только проверяющему, когда выданы все подзадачи).

**[Предложение Claude]**

- `album_issued` — исполнителям и проверяющему, когда альбом перешёл в «Выдан» — вручную или сам, когда выданы все подзадачи; один раз на выдачу.
- `remarks_closed` — исполнителям альбома, когда закрыто последнее открытое замечание к нему.
- Обе — строки в настройках уведомлений («Альбом выдан», «Все замечания закрыты»), по умолчанию включены; ссылка — карточка альбома.

## 8. Чат «без звука» (по желанию)

ТЗ приложения 5.2: «если такой признак появится в Teams — учитывать». Не блокирует 1.0. Если делать: `PUT /api/chats/:id/mute {until: ISO | null}`, в `ChatSummary` — `muted: boolean`; сообщения такого чата — без плашки на сайте и без уведомления Windows, счётчик серый.

## Приёмка

1. Администратор и BIM-менеджер загружают сборку, отмечают «проверена»; сотрудник без права `plugins_manage` — 403 на маршрутах управления.
2. `GET /api/desktop/plugins` у неиспытателя — без пробных; у испытателя — с пробными; файл пробной сборки неиспытателю — 404; `sha256` в ответе совпадает с файлом.
3. Отозванная сборка не раздаётся; событие `desktop:plugins` приходит после проверки и отзыва.
4. Реакции 🔥 и 🎉 ставятся и снимаются, старые на месте.
5. Чат объекта: назначили задачу — `myActiveTasks` вырос, пришёл `chat:list`; выдали — уменьшился.
6. `GET /api/desktop/morning` в выходной — `workday: false`; новое замечание к моему альбому — `newRemarks` +1.
7. Чат поддержки выбран — сообщение с файлами из приложения доходит; не выбран — `supportChatId: null`.
8. Закреплённый чат — вверху списка у себя, у коллег без изменений.
9. Альбом выдан — `album_issued` исполнителям и проверяющему; последнее замечание закрыто — `remarks_closed`.
10. Модульные тесты на права, раздачу каналов и новые события; журнал безопасности пишет действия с реестром.
