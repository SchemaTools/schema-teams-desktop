# План реализации клиента v4

Обновлено 30.10.2026. Работа ведётся в `codex/v4-client`, PR #6; основа — ТЗ v4
с [дополнением для Teams 0.12.1](tz/desktop-0.12.1-addendum.md) и решениями 29.10.
Серверный репозиторий доступен только для чтения. Реальные адреса, установщики,
Excel и журналы остаются локально, вне публичного Git.

## Текущий этап — переход на договоры 0.12.1

Текущий блок **0.7.1** завершает программную часть S2: durable outbox,
Windows query/session-end и явное продолжение/подготовка после возвращения.
Порядок и ограничения — [release-0.7.1](release-0.7.1.md). Реальная доставка
событий Windows и ручная эксплуатационная приёмка открыты. Следующий
независимый этап — Д4, затем Lucide. Актуальный health — **0.12.1-b**;
ниже сохранены основания и история прежних блоков.

Подготовлен блок **0.7.0**: config/capabilities, CAS-команды таймера, новая
подготовка/валидация записи, серверный pick-list, pending/ack и безопасная
автопауза. См. [границы блока](release-0.7.0.md). Окончательные проверки,
установщик и независимая ревизия фиксируются перед публикацией. Следующий
функциональный этап — Д4, затем Lucide и Д7/Д5 по порядку ниже. На границе 0.7.0 S2 был частичным:
постоянная очередь между перезапусками, завершение Windows и UX после
разблокировки остаются открытыми; ручная приёмка не перенесена из 0.6.8.

Найден коммит обмена `092107c` с тремя ответами сервера. Повторно прочитаны
постановка сервера v5 и новые shared-типы. Публичный health стенда сообщает
**0.12.1**. Прежнее ожидание отсутствующих API снято: теперь требуется клиентская
интеграция. Наличие конкретных capabilities после входа ещё проверить.

Порядок и критерии проверки подробно заданы в дополнении:

1. Config/capabilities и новые DTO, сброс при смене входа/сервера.
2. Новый таймер: expected + Idempotency-Key, prepare/prepared/validate-rows,
   pick-list, pending/ack, затем безопасная автопауза. Текущий preflight 0.6.8
   не заменяет серверный CAS и не подтверждает совместимость с 0.12.1.
3. Д4: восемь реакций, myActiveTasks, top до пяти, новые события и quiet.
4. Lucide вместо Phosphor; остальные согласованные решения макета и клавиатуры
   сохраняются, Fluent Emoji реакций остаются отдельными изображениями.
5. Д7: morning и поддержка через upload → support, без добавления отправителя
   в участники; повтор доставки не создаёт второе сообщение.
6. Д5: реестр и UI, затем проверенная загрузка/подпись/установка/откат. Доверенная
   подпись и реальное наполнение реестра ещё не подтверждены.

Шаги Д4–Д7 не закрыты. Серверный код не править, реальные команды и сообщения
ради проверки этого ТЗ не отправлять. Новый установщик/Excel готовить вместе
с проверенным функциональным блоком; старую приёмку сохранить как историю.
Планировщик остаётся отключённым. Ниже — история реализованного 0.6.8 и прежних
ограничений, а не основание снова ждать уже реализованные серверные API.

## Исторический этап — сборка 0.6.8

Блок 0.6.8 дополняет контраст текста проверками пиктограмм и границ ввода. Проверки
охватывают реальные окна Electron с локальной фикстурой, включая четыре шага
мастера и результат быстрого ответа. Метод и ограничения — docs/contrast-audit.md.
Оптимизация DX12 0.6.6 сохранена; новый замер с Revit не проводился.
Никакие журналы и снимки не отправляются автоматически. Старые результаты
Excel сохранены; новые строки 896–991 требуют ручного заполнения.
Мастер первого запуска, прокрутка истории и прежний клиент проверяются вместе
с новым блоком. Каталог плагинов честно обозначен недоступным.
Сборка NotSigned; установка из приложения открыта.
Д4/Д6/Д7 требуют ручной приёмки и серверных
дополнений. Ручные испытания пользователь проведёт позже одной пачкой.
Не отмечать их пройденными по результату автотестов.
Итоговые локальные файлы и номера новых строк сверять перед следующим изменением
Excel; всегда сохранять внесённые пользователем факты.

## Сверка серверных зависимостей 29.10

- В `0.11.2-b` по-прежнему шесть реакций; поля персонального закрепления
  и моих задач в ChatSummary отсутствуют. В регистрации app и exports shared
  нет реестра плагинов. Серверный код Desktop не изменяет.
- У `GET /api/objects` есть `ObjectCard.myTasks`, но только для сотрудников
  без `see_all`; руководителю приходит null. По этому полю можно безопасно
  сопоставлять объект по ID, однако оно не даёт общего решения для всех ролей.
  Не сопоставлять задачи и объекты по названию; null не считать нулём.
- Полный Д4 и Д5 не закрывать по отсутствию ручных испытаний или серверного API.

## Проверка каждого готового блока

Типы, линтер, необходимые модульные и сквозные тесты; визуальная проверка обеих тем.
Из-за посторонних локальных проектов запускать общий check на чистом снимке
исходников, не ослабляя правила линтера. Перед push — проверка приватных данных.
Установщик собирать с прежней приватной конфигурацией стенда. Проверить версию,
содержимое asar и фактическую подпись. Обновить статус, PR #6 и общую Excel-книгу.
