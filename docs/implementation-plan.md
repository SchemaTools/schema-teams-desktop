# План реализации клиента v4

Обновлено 29.10.2026. Работа ведётся в `codex/v4-client`, PR #6; основа — ТЗ v4.
Серверный репозиторий доступен только для чтения. Реальные адреса, установщики,
Excel и журналы остаются локально, вне публичного Git.

## Сделано

- Д1: каркас и установщик.
- Д2/Д3: уведомления, DND, Focus, API/Socket.IO и вход. Исторические ручные
  результаты сохранены; Windows 11 отложена пользователем.
- Д4, 0.4.0–0.4.2: собственный клиент, папки и история, служебные события,
  сетевые пути, скачивание/просмотр/отправка файлов, clipboard PNG, шесть реакций.
- Д4, 0.4.3: цитаты, правка/удаление, закрепление сообщения, поиск в чате,
  явное прочтение в списке, набор текста, сохранение позиции истории,
  переход к новым сообщениям, эмодзи, группировка автора.

## Текущий этап

Блок 0.4.3 реализован: 361 модульный и 45 сквозных тестов пройдены; установщик
собран. Д4 продолжается с экрана «Об объекте» и сверки серверных дополнений.

   соответствующий серверный API и макет до реализации. Не добавлять выдуманные
   поля и маршруты. Проверить актуальную серверную ветку на новые возможности
   из `docs/teams-request.md` (последний подробно сверенный tag — 0.11.2).
2. Д4: при наличии новых серверных полей добавить группы активных объектов,
   реакции огонь/праздник и служебные события. Если API отсутствует, записать
   зависимость; не подменять её локальной имитацией. Закрепление чата в списке
   отличается от уже реализованного закрепления сообщения.
3. Д5: проверить наличие серверного реестра Revit-плагинов. Использовать
   существующие локальные наработки, безопасную загрузку, проверку подписи/хеша
   и правила установленного Revit. Сервер не менять. Отсутствие API не требует
   останавливать независимую работу над Д6.
4. Д6: собственный интерфейс таймера и API учёта времени. Переиспользовать
   существующие сервисы и серверные DTO; при обрыве не обещать неподтверждённую
   паузу. Сверить ранее подготовленное серверное задание о безопасной паузе.
5. Д7: обновление, первый запуск, поддержка, подпись — только в пределах
   доступных API и ранее согласованных полномочий. Сертификаты и ключи не запрашивать
   в чате и не помещать в репозиторий.

## Проверка каждого готового блока

Типы, линтер, необходимые модульные и сквозные тесты; визуальная проверка обеих тем.
Из-за посторонних локальных проектов запускать общий check на чистом снимке
исходников, не ослабляя правила линтера. Перед push — проверка приватных данных.
Установщик собирать с прежней приватной конфигурацией стенда. Проверить версию,
содержимое asar и фактическую подпись. Обновить статус, PR #6 и общую Excel-книгу.
