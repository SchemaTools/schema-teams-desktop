# Клиент 0.7.0: config и безопасный таймер

Блок интеграции Teams 0.12.1 / 0.12.1-b, 30.10.2026. Договоры сверены по
shared desktop-config.ts и time-timer.ts, а также фактическим серверным маршрутам.
Сервер остаётся только для чтения; команды проверяются на локальном HTTP/Socket.IO
стенде. Полная готовность ТЗ v4 и ручная приёмка этим выпуском не объявляются.
S1 реализован; S2 реализован частично. Открыты постоянная очередь команд между
перезапусками, сценарий завершения Windows и UX подтверждения после разблокировки.

`desktop/config` проверяется и хранится в main для текущего входа. Неизвестные
capabilities игнорируются, младшие версии таймерного договора отключены. Управление
таймером требует timerControl >= 2 и корректного CAS-снимка; выход и смена сервера
очищают данные. Пояс и конец дня бюро доступны только для чтения.

Команды таймера передают expected с timerId, revision, currentSegmentFrom и
Idempotency-Key. Неизвестный сетевой исход допускает один повтор того же ключа,
метода и тела; ответы 409/428/400/403 и серверная ошибка не запускают новый запрос.
Подготовка использует prepare-finish; после потерянного ответа доступно чтение
prepared/:requestId. Открытие и закрытие проверки не ставят таймер на паузу.
Перед записью сервер проверяет точные отредактированные строки, finish получает
новый ключ и preparedRequestId. Истечение подготовки показано явно. Изменение
таймера другим устройством блокирует старую форму.
Изменённые строки проверяются с задержкой; поздний ответ прежней проверки не
разрешает запись новых строк. После сетевого отказа доступен явный повтор проверки.
Кнопка «Добавить 15 минут» требует подтверждения: она сдвигает начало первого
интервала назад, увеличивая отработанное время. «Ещё работаю» в напоминании
сохраняет свой прежний смысл.

Выбор и недавние задачи приходят из серверного pick-list; поиск также обращается
к серверу. Идентификатор устройства записывается на диск до первого pending.
Уведомление о полуночи подтверждается ack только после фактического показа popup;
подавление политикой, фокусом или блокировкой подтверждением не считается.
Автопауза при блокировке/сне хранит исходный снимок и время события по serverNow;
при восстановлении связи повторяется тот же envelope. Старое событие таймера A
не нацеливается на B. Автоматического продолжения нет. После перезапуска приложения
незавершённая команда из памяти не восстанавливается: требуется проверка времени.

Исправления по ручной проверке 0.6.8:

- Popup считает уникальные непрочитанные ID; успешный read сбрасывает только сообщения
  до upTo, закрывает прежний popup и при необходимости показывает остаток. Неуспешный
  или поздний read не очищает новые сообщения и данные нового входа.
- «О программе» явно разделяет установленную и опубликованную версии, включая
  равную/более старую опубликованную. После ошибки сохранённая версия помечается
  результатом последней успешной проверки. no_release означает отсутствие публикации.
- Ошибка фото из буфера пока не воспроизведена. Сквозной тест проходит через реальные
  PNG-байты, загрузку, отправку, скачивание и повторное увеличение. Размер по серверному
  источнику не преобразуется; строгая проверка размера сохранена. Сообщения различают
  ошибку имени, размера, сигнатуры и декодирования без вывода приватных данных.

Требуют ручной проверки: исходное проблемное фото из буфера, настоящая полночь,
блокировка/сон и потеря связи на двух устройствах, финальный вид обеих тем.
Исторические результаты Excel сохранены; новые проверки не считаются пройденными
по автотестам. Подпись установщика и последующие Д4–Д7 проверяются отдельно.
