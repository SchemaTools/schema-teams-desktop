# Замер памяти собственного клиента

30.10.2026. Это автоматическая проверка на локальной фикстуре без Revit и модели.
Она не закрывает сценарии 24 и пробную эксплуатацию из раздела 14 ТЗ.

## Метод

Запускается упакованный EXE в новом изолированном профиле с `--hidden`.
После десяти секунд выполняются вход и открытие одного фикстурного чата,
затем все окна скрываются. Метрики собираются каждые десять секунд не меньше
двух минут после входа. Настоящий профиль, адреса бюро, Revit и бизнес-записи
не используются. К процессу подключён инспектор Playwright; принудительной GC нет.

Используется `app.getAppMetrics()` Electron 44.9.1, Chromium 152.0.7977.167.
Измеряется вся группа процессов приложения: main, renderer, GPU, сетевой utility.
Процессы тестового сервера, Playwright и Revit в сумму не входят.
`privateBytes` и `workingSetSize` показаны отдельно в МиБ; складывать их нельзя.
Сумма рабочих наборов может повторно учитывать общие страницы. Поля и единицы —
[Electron MemoryInfo](https://www.electronjs.org/docs/latest/api/structures/memory-info).
Определения сверены с установленными типами 44.9.1; сайт документации показывает latest.

## Найденный пик 0.6.5

В двух отдельных прогонах примерно через 120 секунд после старта появился второй
GPU-процесс. Он исчез к следующей выборке через десять секунд. В корректном прогоне
с `--hidden` максимум составил 280,3 МиБ privateBytes и 480,2 МиБ суммы рабочих
наборов; после пика — 209,1 и 361,4 МиБ соответственно. В первом прогоне пик рабочего
набора был 462,5 МиБ. Его стартовая выборка не считается скрытой: `ready-to-show`
успел показать окно после раннего `hide`; последующие выборки после входа скрыты.

Превышение ориентира 400 из ТЗ сообщено руководителю до продолжения. Это не
результат ручного замера с Revit и не доказательство постоянной утечки.

## Изменение 0.6.6

В Windows до готовности Electron добавлен
`disable-gpu-process-for-dx12-info-collection`. В исходниках используемого Chromium
этот переключатель отменяет отдельный несандбоксированный процесс сбора сведений
DX12/DirectML. Основной GPU-процесс остаётся для отрисовки. Получение полного
диагностического отчёта DX12 через Chromium может стать неполным; приложение
этим отчётом не пользуется.

Основание — точный Chromium 152.0.7977.167:
[планирование сбора через 120 секунд и проверка переключателя](https://github.com/chromium/chromium/blob/152.0.7977.167/content/browser/gpu/gpu_data_manager_impl_private.cc),
[определение переключателя](https://github.com/chromium/chromium/blob/152.0.7977.167/gpu/config/gpu_switches.cc).
Версия Chromium взята из [DEPS Electron 44.9.1](https://github.com/electron/electron/blob/v44.9.1/DEPS).
Совпадение времени и типа процесса было основанием для проверки; итог оценивается
повторным запуском упакованной версии.

## Итог сравнения

| Показатель за 120 с скрытого клиента после входа | 0.6.5 | 0.6.6 |
| --- | ---: | ---: |
| Максимум privateBytes, МиБ | 280,3 | 235,4 |
| Максимум суммы рабочих наборов, МиБ | 480,2 | 377,8 |
| Максимум процессов приложения | 5 | 4 |
| Максимум GPU-процессов | 2 | 1 |
| PrivateBytes в последней выборке, МиБ | 209,1 | 219,7 |
| Сумма рабочих наборов в последней выборке, МиБ | 361,4 | 367,0 |

В исправленном прогоне на отметке около 120 с от старта второго GPU-процесса
не появилось. Это подтверждает устранение наблюдавшегося краткого пика в этой
конфигурации. Постоянный расход не уменьшился: конечные значения немного выше,
что не скрывается под сравнением максимумов. Другие драйверы, большая переписка
с фотографиями, Revit и Windows 11 требуют отдельных замеров.

Полный автоматический набор: 568 модульных и 108 сквозных тестов. В native EXE
проверены прежние функции, изображения/снимок своего окна, ZIP и служебный журнал.
Результаты и исходные JSON остаются локально; никаких отметок ручного прохождения
по этим числам не выставлено.

## Повторение

После `npm ci` и `npm run dist` на Windows:

```powershell
node scripts/measure-memory.mjs --seconds 120 --output private/memory-repeat.json
```

Можно указать другой упакованный EXE через `--executable`. Существующий файл
результата не перезаписывается. Неполный/прерванный прогон имеет `complete:false`.
Выборка скрытого этапа отклоняется, если какое-либо окно видно. Время, PID и сырые
метрики остаются в локальном JSON; в Git публикуется только обезличенный итог.

Ручная проверка: приложение в трее рядом с Revit и обычной моделью, указать версию
программы, метод/единицы, число процессов, устойчивое значение и краткие пики.
Ожидаемые 120–250 МБ в ТЗ имеют низкую уверенность; при значении выше 400 сообщить
руководителю. Windows 11 и этот ручной замер пока открыты.
