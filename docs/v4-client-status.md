# Собственный клиент v4 — 0.5.1

29.10.2026, ветка `codex/v4-client`, основа `stage/d1` / `cfff98f`.
Актуальные документы также проверены в обновлении `docs/main-tz-v4` / `a08c89b`:
ТЗ и макет v4, сверка API и постановка Teams. Прежний мост со страницей
в этой реализации не используется. Серверный репозиторий не изменялся.

## Собственный таймер Д6

- В 0.5.1 добавлены настройки напоминания с шагом 30 минут и конец рабочего дня
  бюро только для чтения. Время напоминания относится к календарю компьютера,
  конец дня — к данным сервера. Настройка сохраняется локально без изменения таймера.
- Вечернее напоминание использует текущую задачу и подтверждённый run.
  Кнопка завершения открывает собственное окно проверки, «Ещё работаю» закрывает
  уведомление. Напоминание не посылает pause/resume/finish. DND, Focus, lock/suspend,
  тихие часы, звук и скрытие текста учитываются. При неизвестном поясе тихих часов
  действует прежняя консервативная политика: popup не разрешается.
- День считается показанным только после фактического показа; подавленный popup
  можно повторить не раньше минуты. Последний показанный локальный день хранится
  по пользователю и переживает перезапуск. Старые кнопки не действуют после смены
  задачи, входа, дня, настройки или ухода в offline.
- Проверен существующий `timer_stopped` tag 0.11.2-b: сервер создаёт утреннее
  событие, а клиент показывает его итог и «Проверить запись» с серверной ссылкой
  на день трудозатрат. Клиент не останавливает таймер в полночь и не создаёт записей
  по выдуманному часовому поясу. Серверный cron и реальная ночь ещё требуют приёмки.

- В 0.5.0 добавлены собственные выбор задачи и окно записи трудозатрат.
  Поиск по марке, названию и объекту; три недавние задачи сохраняются отдельно
  для каждого пользователя. Кнопка назначения открывает выбор с подсветкой задачи.
- Карточка трея и главное окно используют одно серверное состояние `time:timer`.
  Пауза/продолжение, явный сброс с подтверждением; открытие окна не меняет таймер.
  «Закончить и проверить» сначала ставит его на паузу и читает серверное предложение.
  Интервалы редактируются с шагом 30 минут, примечание — до 500 знаков.
- При смене задачи старая записывается первой; новая запускается только после
  подтверждённого finish. Нулевое округление не создаёт фиктивную запись.
  Ошибка строки выделяется, введённые данные сохраняются. Неизвестный исход
  не повторяется автоматически и требует нового просмотра актуальных интервалов.
- Перед ручной командой main заново сверяет version, taskId и startedAt;
  команды одного входа сериализованы. Это уменьшает риск устаревшего окна,
  **но не заменяет атомарный CAS на сервере**. При сетевом обрыве записи запрещены.
  Старые ответы и предупреждения очищаются при смене входа.
- После lock/suspend показан период отсутствия и предупреждение о неподтверждённой
  паузе. Существующий пассивный TimerAbsence перенесён из прежней реализации.
  Автопауза, очередь команд и безопасный повтор finish остаются открытыми
  до серверной доработки. Реальная полночь требует отдельной проверки сервера.
  Д6 целиком не закрыт.

## Продолжение Д4 после ручных проверок

- В 0.4.4 добавлена панель «Об объекте»: реквизиты, заказчик, адрес,
  ответственные, текущая и остальные стадии, пути и переход на сайт объекта.
  Main сначала проверяет доступ к чату и берёт objectId из его серверного
  описания; renderer передаёт только chatId. Ответ объекта сверяется по ID,
  посторонние поля отбрасываются. Права объекта дополнительно проверяет сервер.
- Панель закрывается по Escape, возвращает фокус кнопке, работает в обеих
  темах и узком окне. Отказ/ошибка допускает повтор, не меняя черновик;
  поздний ответ после выхода не возвращает сведения другого входа.
- Служебные упоминания, назначения и сроки имеют разные цвета и пиктограммы.
  `due_soon`, `overdue`, `due_changed` получили соответствующие подписи.
  События праздника не выдумываются при отсутствии серверного источника.
- В 0.4.3 добавлены ответ с цитатой и переход к исходному сообщению. Отмена
  цитаты сохраняет текст и файлы. Номер цитаты входит в intent отправки;
  явный повтор того же payload сохраняет ключ, смена цитаты создаёт новый.
- Свои сообщения можно править и удалять по серверному `canEdit` (24 часа).
  Правка не меняет отдельный черновик нового сообщения. Удаление требует
  подтверждения в интерфейсе, после ответа сервера остаётся плашка. Неизвестный
  исход не повторяется автоматически; текст правки сохраняется.
- Закреплённое сообщение показывается под шапкой и открывает исходное.
  Закрепление и открепление доступны по `canPin`; это закрепление сообщения,
  персональное закрепление чата по-прежнему требует серверного дополнения.
- Поиск внутри чата обращается к серверу по явной команде: минимум два знака,
  до 30 последних совпадений, переход к сообщению без потери черновика.
  «Прочитано» в строке списка — отдельное явное действие; main берёт последний
  ID из своего серверного списка, не требуя открыть этот разговор.
- «Печатает…» отправляется через текущий Socket.IO не чаще раза в 3 секунды,
  входящее состояние гаснет через 5 секунд. Оно не запускает HTTP-перечитывание.
  Новое сообщение сохраняет позицию чтения истории; есть кнопка к последним.
  Исправлена гонка плавной прокрутки с фоновым обновлением.
- Подряд идущие сообщения одного автора группируются: имя в начале,
  аватар и хвостик у последнего. Имена имеют устойчивые цвета для обеих тем.
  Кнопка эмодзи вставляет шесть обычных эмодзи в текст сообщения.
- Скрепка выбирает до 10 файлов по 50 MiB. Main проверяет права чата, читает
  выбранные файлы и загружает байты; renderer получает только метаданные.
  Черновик показывает файлы до отправки, поддерживает удаление и сообщение без текста.
  При частичной ошибке уже загруженные файлы сохраняются в черновике.
- Вставка изображения через Ctrl+V использует `clipboard.read()` Electron 44.
  PNG проверяется до загрузки: до 50 MiB, 8192 px на сторону и 20 Mi pixels.
  Текстовая вставка сохраняет обычное поведение. После выхода поздние результаты
  не попадают в другой вход; native picker сериализован с чтением и загрузкой.
- Шесть серверных реакций (`like`, `done`, `look`, `heart`, `laugh`, `question`)
  ставятся и снимаются после подтверждения API. Счётчик и собственная отметка
  обновляются по ответу сервера. Локальные Fluent Emoji 3D поставляются с MIT;
  reduced motion отключает анимацию. Дополнительные реакции ждут серверного API.
- Сетевой путь предлагает только «Показать в папке». Main также принудительно
  выбирает reveal, поэтому старый запрос не запускает сетевой файл.
- Вложения скачиваются из своего чата в «Загрузки». Есть команды «Скачать»,
  «Открыть» и «Показать в папке». Коллизия имени создаёт отдельный файл;
  изменённая локальная копия не подменяет последующее открытие вложения.
- PNG/JPEG/GIF/WebP показываются в сообщении и увеличиваются в локальном окне
  просмотра. Байты получает только main. Случайные адреса собственной схемы
  действуют в текущем входе, не раскрывая адрес сервера, cookie или путь на диске.
- Смена входа прерывает сетевые запросы и отзывает просмотр. Перед скачиванием
  main проверяет принадлежность файла неудалённому сообщению доступного чата.
  Redirect, превышение размера и усечённый ответ отвергаются. Не больше двух
  загрузок одновременно; команды пользователя ожидают свободный слот.
- Исполняемые, активные и неизвестные типы не открываются автоматически:
  после явной команды доступно сохранение/показ в папке. Windows получает метку
  скачанного файла без записи приватного адреса источника.
- Плагины остаются Д5 после серверного реестра. Собственный ручной таймер
  подключён в 0.5.0; серверные зависимости Д6 и ручная приёмка остаются открытыми.
  Отсутствующие возможности не засчитываются исправлениями Д4.

## Работает в этой сборке

- Локальный React-интерфейс с папками, списком чатов и перепиской по макету v4.
  Светлая, тёмная и системная тема; Phosphor, Inter и IBM Plex Mono загружаются
  из сборки, без внешних запросов из окна интерфейса.
- Отдельное sandbox-окно входа с `persist:teams`; пароль остаётся на странице
  Teams. Смена временного пароля отслеживается повторным `/api/auth/me` даже
  без изменения cookie или URL. Cookie сохраняются после перезапуска.
- Единственный типизированный API-клиент в main: версия, вход, чаты, детали,
  история, отправка текста, прочтение, события, настройки уведомлений и Focus.
  Cookie/CSRF не пересылаются в renderer или журналы.
- Настоящий Node-клиент Socket.IO с cookie в handshake; переподключение
  через 1/2/5/10/30 секунд и перечитывание данных. Событие `session` очищает
  прежний кэш и проверяет вход заново, поскольку оно означает также смену прав.
- История с подгрузкой, прямой переход к сообщению, Enter отправляет,
  Shift+Enter переносит строку. Неизвестный исход сохраняет текст и ключ
  отправки; явный повтор того же текста использует тот же ключ. Новый текст —
  новый ключ. Автоматической офлайн-очереди сообщений нет.
- Прочтение требует видимого, сфокусированного главного окна и выбранного
  разговора. Явная кнопка «Прочитано» уведомления — отдельное намерение.
- Служебный чат «Schema Teams» из колокольчика, отметка прочтения, переход
  к чату/сообщению либо на сайт. Права на данные по-прежнему проверяет сервер.
- Карточка трея с Focus, темой и настоящим быстрым ответом последнему
  непрочитанному чату; счётчики на значке и панели задач.
- Проверенные UNC-валидатор, worker с тайм-аутом 3 с и ограничением двух процессов,
  показ доступного пути в Проводнике и диалог недоступности.

## Граница безопасности и переходы входа

Во всех окнах sandbox/contextIsolation, без Node; CSP локального интерфейса
запрещает сеть, внешние ресурсы и eval. IPC проверяет webContents, главный фрейм,
точный локальный URL и ограниченную схему команды. Нет общего fetch/URL/headers RPC.
Каждая команда пользователя несёт захваченный epoch входа. Старый IPC не может
выполниться от имени нового пользователя. Результаты тоже проверяются после await.

CSRF-refresh повторяет мутацию только после конкретного 403 `csrf`, ровно один
раз и с тем же владельцем; неизвестная отправка автоматически не повторяется.
Результат send сверяется с чатом, автором и текстом намерения. Запрос ограничен
15 секундами вместе с телом, ответ — 2 MiB. Смена входа отменяет ожидания.
Logout сериализован до первого await; новый вход не начинается до его завершения,
поздний ответ не должен удалять сменившуюся cookie. Кэш и старые черновики очищаются.

## Что ещё не считается реализованным

- Полная приёмка Д3/Д4/Д6. Повтор изменённых сценариев 0.5.1 на настоящем сервере,
  Windows 11 и пилот рядом с Revit ещё не выполнены.
- Для неподдержанного сложного содержимого (карточки, стикеры, опросы) остаётся переход
  «Открыть в Teams». Обычные вложения обрабатываются собственным клиентом.
- Плагины Revit (Д5), полный таймер (Д6), обновление приложения, поддержка,
  первый запуск и подпись (Д7). Папка плагинов недоступна; фиктивных данных нет.
- Серверные дополнения из актуальной редакции SERVER-CHAT-001: активные задачи
  на объекте, новые реакции и события, персональное закрепление чатов.

Уведомления сохраняют прямое указание руководителя: Enter отправляет,
Shift+Enter переносит строку. Используются собственные окна, поэтому они не
попадают в центр уведомлений Windows. Родные окна в ТЗ v4 и эта клавиатура
остаются расхождением, которое нельзя скрывать. Учёт Windows DND повторно
проверяется непосредственно перед показом; звук зависит от успешного показа.

Обычный `chat:message` не содержит `quiet`. Перед показом main читает
`/api/notification-settings`, не дублируя эти настройки в своём UI. Сервер считает
тишину в `Bureau.timezone`, а этот пояс отсутствует в просмотренных auth/health/settings
DTO версии 0.11.2. Поэтому при настроенной тишине и неизвестном поясе обычное
всплывающее сообщение подавляется. При `quiet:null` разрешается; серверный
`NotificationPush.quiet` учитывается как есть. Подстановка часового пояса ПК
или выдуманного интервала не применяется. Этот пробел требует серверных метаданных.

## Проверки

- Автоматические тесты работают только с заглушкой: HTTP, CSRF, HttpOnly-cookie
  и настоящий Socket.IO; настоящий сервер и реальные сообщения не менялись.
- Сохранены семь проверок каркаса, их ожидания обновлены под локальное окно v4:
  вход/перезапуск, скрытие, автозапуск, один экземпляр, внешние ссылки и offline.
- Проверяются утечка cookie/CSRF/текста в renderer и журналы, потерянный ответ
  с повтором без дубля, reconnect, временный пароль без навигации, старый epoch,
  видимое прочтение, logout mutex и поздний logout другого входа.
- Итоговый `npm run check` на чистом снимке подготовленных файлов: типы main,
  renderer и тестов, ESLint, Prettier, **446 модульных и 71 сквозной тест** пройдены.
  Тесты не отключались. Дополнительно проверены загрузка байтов, лимиты и обрыв,
  права на вложение, выход во время скачивания, подмена имени/типа, коллизия файла,
  просмотр фото, повтор после ошибки и увеличение снимка после вытеснения кэша.
- Дополнительно проверены raw upload с CSRF, clipboard PNG, файл без текста,
  частичная ошибка выбора, read-only, неизвестный исход и повтор с тем же ключом,
  выход во время загрузки, постановка/снятие реакций, отказ 403, reduced motion
  и доступность локальных картинок без сети. Буфер ОС тестами не изменялся.
- Новые сценарии: цитата/повтор/отмена, правка и сохранение другого черновика,
  подтверждение удаления, закрепление/открепление и права, 403/неизвестный исход,
  поздняя правка другого входа, набор/тайм-аут, история, поиск, явное прочтение,
  вставка эмодзи и группировка сообщений. Ручные испытания отложены пользователем.
- Дополнительно проверены сведения объекта, отсутствие кнопки в личном чате,
  права и повтор, архивный объект, узкое окно, обе темы, закрытие и фокус,
  ссылка на сайт без открытия настоящего браузера, выход во время загрузки.
  Проверка геометрии реакций читает обе границы одним снимком DOM и учитывает
  положение панели во время перехода; текст не перекрывается.
- Дополнительно проверены ручной таймер, сериализация и предварительная сверка,
  смена владельца/поздний ответ, серверное округление, ошибка строки, нулевые строки,
  неизвестный finish без запуска следующей задачи, подтверждение сброса, offline,
  недавние после перезапуска, назначение и настоящая карточка трея. После lock/suspend
  проверено пассивное предупреждение без автоматических команд.
- У миниатюры убрана вторая browser lazy-загрузка: видимость уже контролируется
  IntersectionObserver и очередью приложения. Это устраняет гонку загрузки токена
  в длинной ленте. Проверка 14 фотографий и повтор/увеличение сохранены.
- Для 0.5.1 проверены локальное время/получасовые границы, один фактический показ
  по пользователю и дню, повтор после подавления, DND/Focus/lock/quiet, поздняя
  политика, старые кнопки, скрытие текста и отсутствие звука при отказе.
  Проверены настройки, сохранение/ошибка, перезапуск и серверное `timer_stopped`

  Адрес прежнего тестового стенда задан только в локальной сборке. Подписи пока
  нет; установщик, скриншоты и пользовательский Excel в Git не добавляются.
- Снимки светлого и тёмного чата и меню трея просмотрены. Новые проверки

- Дополнительно запущен упакованный EXE 0.5.1 с отдельным профилем и локальным

  объекта, запуск/пауза/однократная запись таймера и сохранение настроек пройдены.
  Main/API/renderer и CSS сверены с содержимым asar.

Ручные результаты хранятся в единой локальной книге. Прежние отметки и факты
