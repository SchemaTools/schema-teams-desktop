# Schema Teams Desktop 0.12.0 — проверка и явный запуск обновления

В существующий раздел «О программе» подключён поток загрузки, проверки и
подтверждения выхода для обновления. Main хранит полное предложение сервера;
renderer получает только непрозрачные идентификаторы, состояние и прогресс.
Изменение файла, SHA, размера, заметок, версии или контекста отменяет старое
разрешение. Публичная проверка latest по-прежнему доступна без входа.

Загрузчик ограничен 512 МиБ, проверяет размер и SHA, использует собственный
временный каталог и один поток. Подлинный receipt связан с исходной identity
файла; повтор, отмена и очистка не присваивают заменённые или переданные
установщику файлы. Подпись проверяется отдельным Desktop purpose Windows-helper.
Прежний двухаргументный режим проверки Revit-плагинов сохраняет предел 200 МиБ.

Для запуска требуются доверенная подпись установленного приложения и установщика,
одинаковый одобренный DER сертификата, повторная проверка обоих файлов и свежего
latest. Изменение identity, размера, времени изменения байтов или метаданных или хеша
останавливает операцию. Монотонный срок подтверждения не продлевается переводом
системных часов. Проверки не заявляются атомарной блокировкой файла до CreateProcess.

Перед выходом пользователь видит число несохранённых черновиков всех чатов и
явно выбирает «Вернуться» либо «Закрыть и установить». Открытые формы таймера,
отчёта, мастера настройки и правки сообщения нужно закончить обычным способом.
Неоконченные или неподтверждённые отправки не считаются черновиками для удаления.
Несохранённые быстрые ответы и открытое меню трея также блокируют запуск.
Живое окно popup с полем ответа блокирует запуск даже до получения сведений о
черновике. Во время проверки выхода новые popup не создаются; допуск повторно
проверяется после асинхронного запроса политики Windows.

После подтверждения UI запрещает новые действия, а общий main lease закрывает
новые IPC-операции, запись API и замену серверного Host. Durable очередь автопауз
сохраняется. Перед запуском проверки выполняются заново; отмена или ошибка
возвращает управление. Runner передаёт только проверенный собственный путь,
пустой список аргументов и `shell=false`; нет `/S`, `--updated` или повышения прав.
Обычный выход с сохранением cookie начинается только после события `spawn`.
Запуск процесса не означает успешной установки.

## Границы готовности

- Список доверенных Desktop издателей пуст. Revit publisher policy не выдаёт
  доверие Desktop. Env, settings и IPC не позволяют подменить сертификат или runner.
- Неподписанное установленное приложение запрещает этот поток даже при корректном
  установщике: загрузка не создаёт первоначальное доверие.
- Настоящий NSIS/U3 запуск, установка, обновление установленного клиента и
  положительная ручная проверка подписи не выполнялись. Тесты используют инертные
  временные файлы, явно подставную проверку издателя и spy запуска.
- Реальный WinTrust helper отдельно проверен только чтением PE. Полный набор
  автоматических проверок и ревизия фиксируются перед публикацией блока.
- Ранее внесённые факты Excel не переоцениваются. Ручная приёмка остаётся открытой.
- Последний NSIS-установщик — 0.10.0; каталог приложения 0.11.0 сохранён.
  Упаковка NSIS ожидает отдельного разрешения; 0.12.0 этим документом не объявлен
  установленным или принятым пользователем.

Следующий программный блок — интеграция датчика заставки с безопасной автопаузой.
