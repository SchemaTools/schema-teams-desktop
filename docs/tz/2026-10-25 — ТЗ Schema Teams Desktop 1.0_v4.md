## 1. Что это и границы

Настольное приложение Schema Teams для Windows 10/11 на компьютерах бюро. Живёт в трее и даёт то, чего не может браузер на HTTP-странице: уведомления Windows с быстрым ответом, чат под рукой, кнопки учёта времени у часов, открытие сетевых папок, обновление плагинов Revit. Всё остальное — на сайте Teams в браузере.

## 2. Устройство

### 2.1. Стек

- **[Решение]** Electron, только Windows 10/11 x64.
- **[Предложение Claude]** TypeScript `strict`; сборка — `electron-builder` (MIT), установщик NSIS; тесты — Vitest (логика главного процесса и клиента API) и Playwright `_electron` (сквозные, против заглушки сервера).
- **[Предложение Claude]** Интерфейс окна — React 18 (MIT). Оформление — свой набор переменных по разделу 2.5 (не классы дизайн-системы сайта): акцент тот же, что у сайта, остальное — вид «Мессенджер».
- **[Решение 25.10]** Пиктограммы — **Phosphor Icons** (`@phosphor-icons/react`, MIT), эмодзи реакций — **Microsoft Fluent Emoji 3D** (MIT), картинки лежат в сборке приложения, не грузятся из интернета. Шрифты Inter и IBM Plex Mono (OFL-1.1 — шрифты, не код). Всё — строкой в `docs/decisions.md` с лицензиями.
- **[Решение] Лицензии.** `ffmpeg.dll` (LGPL-2.1) в поставке Electron — исключение из правила лицензий бюро: приложение внутреннее и отдельно не продаётся (16.10.2026). Других зависимостей под LGPL/GPL не добавлять.

### 2.2. Главная мысль: свой клиент, сайт — для остального

**[Решение 25.10]** (заменяет «тонкую оболочку» v2)

- **Окно** — свой интерфейс приложения: папки «Все / Объекты / Личные / События / Плагины», чаты, служебный чат уведомлений, плагины Revit, настройки. Сайт Teams в окне не показывается.
- **Вход** — страница входа Teams в маленьком окне с постоянным разделом `session.fromPartition('persist:teams')`. После входа cookie сессии (`st_session`) остаётся в этом разделе; пароль приложение не видит и не хранит. Сессия гаснет через 14 дней без активности — тогда снова окно входа.
- **Вызовы API** — из главного процесса через `session.fromPartition('persist:teams').fetch` (cookie подставляет Electron). Окно интерфейса ходит к серверу **только через главный процесс** (IPC), само сетевых запросов не делает.
- **Соединение реального времени** — свой клиент Socket.IO в главном процессе с той же cookie, комната пользователя: `notification` (флаг `quiet`), `chat:message`, `chat:read`, `chat:list`, `session`.
- **Переходы на сайт** — `shell.openExternal` с адресом сервера и путём (`/albums/<id>`, `/my`, …). Вход в браузере — свой, как обычно.
- **[Уверенность низкая]** Защита от подделки запросов (CSRF) и заголовки, которые сервер требует от клиента, — сверить с кодом сервера до Д3 (раздел 3).

Плюс: чат и уведомления работают, даже когда окно закрыто, и не зависят от вёрстки сайта. Минус: вторая копия чата — при изменении API чата на сервере приложение надо обновлять (раздел 3.3).

### 2.4. Безопасность

- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false` во всех окнах.
- Окна с содержимым сервера (вход, таймер) получают только узкий `preload`: закрыть окно, сообщить «готово». Сверка `origin` с адресом сервера на каждый вызов.
- **Текст сообщений, имена файлов, подписи — недоверенные данные.** Выводить только как текст (никакого `innerHTML` и HTML из сообщений); ссылки в сообщениях — в браузер, только `http`/`https`; пути `\\…` — по правилам раздела 7.
- Картинки и файлы чата скачиваются главным процессом через раздел `persist:teams` и отдаются окну по своей схеме (`protocol.handle`), без прямых адресов сервера в окне.
- Content-Security-Policy окна: только свои ресурсы, без `unsafe-eval`, без внешних адресов.
- Не открывать новые окна (`setWindowOpenHandler` → запрет или внешний браузер).
- Один экземпляр (`requestSingleInstanceLock`); повторный запуск показывает окно.

- Контраст текста — не ниже 4,5:1 в обеих темах, у пиктограмм и рамок — 3:1.
- Цвет никогда не единственный носитель смысла: **у каждого состояния — пиктограмма и слово** («⚠ На исправлении», «⏱ до 04.11», «✕ было 24.10 → ✓ стало 31.10», «◐ проба»).

**Формы.** Разные формы для разных вещей:
- люди — круглые аватары с цветным градиентом (цвет — по человеку, постоянный);
- объекты (чаты объектов, плагины) — скруглённые квадраты с маркой (радиус ≈ 30 % стороны);
- служебный чат «Schema Teams» — мягкая «капля» со знаком Schema.

**Размеры — одна шкала, ничего не выпячивать** (решение руководителя: «принцип пропорций и соразмерности»):
- текст 12 / 13 / 15 px (сообщения — 15), заголовки 15–18 px;
- кнопки 30–34 px, кнопка отправки 44 px, строки списка ≈ 64 px, аватары 48 / 34 px;
- скругления: кнопки и плашки — полностью, карточки 12–16 px, пузыри 14 px с «хвостиком» у последнего в группе, окна 12 px.

**Пиктограммы — Phosphor, двухтоновое начертание** (контур + заливка 20 %); у выбранного раздела в колонке папок и у кнопки отправки — залитое. Размеры 16 / 20 / 24 px. Эмодзи в кнопках не использовать.

**Реакции — Fluent Emoji 3D, анимированные:**
- панель быстрых реакций по наведению на сообщение: 👍 ❤️ 🔥 ✅ 👀 🎉 и «ещё»; эмодзи в панели слегка покачиваются, под мышью увеличиваются;
- поставленная реакция — плашка «эмодзи + число» под сообщением; своя — залита акцентом;
- при постановке эмодзи вспыхивает и пружинит, вокруг расходится кольцо (≈ 0,5 с).

**Стекло.** Закреплённое сообщение и кнопки под карточками служебного чата — полупрозрачные с размытием фона (`backdrop-filter`), чтобы сквозь них был виден фон чата.

**Движение.** Пружинка у реакций и кнопки отправки при наведении (≈ 0,45 с), появление реакции, конфетти праздника (6.2). Все анимации выключаются, если в Windows включено «Уменьшить движение» (`prefers-reduced-motion`).

### 3.2. Соединение

- Подключение после входа; при обрыве — повтор с нарастающей паузой (1, 2, 5, 10, 30 с), значок серый с «!» (Д-С-1).
- После восстановления — дозапрос пропущенного: список чатов, счётчики, новые уведомления с момента обрыва (по времени последнего события).
- Событие `session` о выходе или истечении — счётчик пуст, меню «Войти», уведомлений нет, окно входа по щелчку.

### 3.3. Совместимость

- При запуске приложение сверяет версию сервера: ниже 0.10.0 — «Нужен Schema Teams 0.10.0 или новее», дальше не пускать.
- Клиент API — один модуль `src/main/api/` с типами ответов. Неизвестные поля пропускать, отсутствие обязательного поля — ошибка в журнал и мягкая деградация (например, без реакций), а не падение.

### 3.4. Что нужно от сервера

Отдельная постановка для `schema-teams` (номер версии — по плану Teams) по итогам сверки 3.1:

- **[Решение 25.10] Реестр плагинов в Teams** вместо папки на сервере, куда сборки выкладываются сейчас. **[Предложение Claude]** по устройству: `GET /api/desktop/plugins` → список плагинов с версиями, каналом («рабочая» / «пробная»), признаком «проверена», ссылкой на файл, `sha256`, «Что нового». Загружают сборки, ставят «проверена» и ведут список испытателей **администратор и BIM-менеджер** (решение руководителя 25.10).

## 5. Уведомления Windows

### 5.1. Чем показывать — итоги опыта Д2

- **[Решение по опыту Д2]** Родные уведомления Windows: попадают в центр уведомлений и подчиняются «Не беспокоить» Windows. На Windows 10 (22.10) поле ответа и кнопки работают; Windows 11 — допроверка второй сборкой.
- Обязательно (находки Д2, `docs/decisions.md`):
  - установщик пишет регистрацию `HKCU\Software\Classes\AppUserModelId\<AppUserModelId>` (`DisplayName`, `IconUri`, `CustomActivator`) и стирает её при удалении — без неё Windows 10 не показывает всплывающее окно;
  - постоянный код активатора (`setToastActivatorCLSID`);
  - каждое нажатие приходит дважды — отбрасывать повтор по метке уведомления и времени;
  - своё уведомление `toastXml` с кнопкой **«Отправить»** словом на Windows 10 и 11 (**[Решение 25.10]**, вместо «Reply» и «➤»);
  - запуск из уведомления при закрытом приложении (`-Embedding`) — ответ обрабатывается, журнал пишется, «Открыть» показывает окно;
  - уведомление, которое Windows сразу отбросила, считается непоказанным — непрочитанное остаётся в счётчике;
  - сообщения одного чата — одной группой в центре уведомлений (`header`).

### 5.2. Когда показывать

**[Решение 25.10]** Решает приложение (раньше — страница):

1. Событие сокета: `notification` без `quiet`, `chat:message` (не своё), упоминание.
2. «Фокус» (состояние с сервера): пока включён, проходят только @упоминания. Остальное копится; после фокуса — одно уведомление «Пока вы были в фокусе: N сообщ. в M чатах, упоминаний K» с кнопкой «Открыть чат».
3. Тихие часы и выбор событий — настройки пользователя в Teams, сервер помечает такие события `quiet`. **В приложении эти настройки не дублируются**, в настройках — ссылка на сайт.
4. Не показывать, если окно видно и в фокусе, а открыт этот чат.
5. Чат «без звука» — если такой признак появится в Teams, учитывать.

## 7. Сетевые пути

### 7.1. Откуда

Путь `\\сервер\…` в сообщении чата приложение показывает карточкой: путь, «Открыть», для файла — «Показать в папке», «Скопировать путь» (v1, Д-П-1, Д-П-2).

### 7.2. Правила открытия

- Принимаются только пути UNC вида `\\server\share\…`. Без `..`, без `file://`, без букв дисков и без адресов устройств Windows (начинаются с «\\?» или «\\.»).
- **Папка** — `shell.openPath` → Проводник под правами сотрудника.
- **Файл** — открыть в программе по умолчанию. Исключение — исполняемые и скрипты (`exe, msi, bat, cmd, com, scr, ps1, vbs, vbe, js, jse, wsf, hta, lnk, reg, cpl, jar`): только «Показать в папке» и текст «Такие файлы не открываются из Teams — только папка с ним».
- **Проверка доступности** — `fs.stat` с тайм-аутом 3 с. Нет ответа или ошибка → окно «Папка недоступна» с путём, пояснением «нет доступа, сервер выключен или вы не в офисной сети», «Скопировать путь» и «Понятно» (v1, Д-П-4).
- Каждое открытие — строка в журнале (путь, результат), без содержимого.

### 7.3. Не проверено

- **[Уверенность низкая]** Все ли компьютеры видят папки сервера бюро под своими учётными записями — на пробной сборке.

## 8. Плагины Revit

**[Решение 25.10]** Входит в 1.0 (раньше — отдельным этапом).

### 8.1. Что делает

- Держит плагины бюро актуальными на компьютере: ставит, обновляет, возвращает прошлую версию.
- **Только проверенные сборки** ставятся сами (В3). Пробные — только у назначенных испытателей с включённым переключателем «Пробные» (В4).
- Ставит в **каждую установленную версию Revit** (2025, 2026) — по списку папок `%APPDATA%\Autodesk\Revit\Addins\<год>` и установленных Revit.
- **Без прав администратора** — в профиль пользователя.

### 8.2. Откуда берёт сборки

- **[Решение 25.10]** Источник — **реестр плагинов в Teams** (раздел 3.4): плагин, версия, канал, «проверена», версии Revit, ссылка на файл, размер, `sha256`, «Что нового». Папка на сервере, куда сборки выкладываются сейчас, приложением не читается; перенос сборок в реестр — в постановке Teams. Проверка — при запуске, раз в 6 часов и по «Проверить сейчас».
- Признак «проверена» ставят администратор или BIM-менеджер после испытания сборки (порядок плагинов бюро: сборка → испытание → выдача).

### 8.3. Установка

- Загрузка во временную папку, сверка `sha256`, **проверка подписи** каждого `.dll` сертификатом «Schema Bureau Revit Plugins» (`WinVerifyTrust` или аналог). Не совпало — не ставить, ошибка в журнал и в окне.
- **Revit открыт** (процесс `Revit.exe`) — обновление ждёт: статус «Ждёт закрытия Revit», полоса в окне, уведомление «Готовы обновления…». Как только все процессы Revit закрыты — установка без вопросов и уведомление «Плагины обновлены — можно открывать Revit».
- Revit запущен во время установки — установка этого плагина откатывается, повтор после закрытия.
- Установка атомарна: новая версия раскладывается во временную папку и подменяет старую одним переименованием; файл `.addin` — последним.
- Прошлая версия хранится в `%LOCALAPPDATA%\Schema Teams\plugins\<плагин>\<версия>` (одна предыдущая) — для «Вернуть».
- Общие библиотеки (Schema.Tools) ставятся вместе с плагинами, которым они нужны; несовместимое сочетание версий не ставится.

### 8.4. Экран «Плагины Revit» (макет v4, экран 3)

Страница в стиле настроек, колонка по центру (до 640 px):

- **Плашка состояния** на синем бюро: кольцо «актуально N/M», одна фраза о том, что будет дальше («Ещё 2 обновления поставим сами, как только вы закроете Revit 2025»), кнопка «Проверить». В общей шкале размеров, без выпячивания.
- **Группы карточкой:** «Ждут закрытия Revit», «Установлено», «Ошибки» (если есть). Строка: цветной значок-скруглённый квадрат с сокращением плагина, название, версия «1.42 → 1.43» и версии Revit, справа — «Что нового» или плашка состояния со значком и словом («✓ свежий», «◐ проба», «⚠ не установлен»), ход загрузки — полоской.
- По «Что нового» — список изменений сборки, «Вернуть <прошлую версию>», «Подпись проверена · сборка выложена <дата>».
- **Настройки здесь же** переключателями с пиктограммами: «Обновлять автоматически» (только проверенные сборки), «Пробные сборки» (виден только испытателям).
- Автообновление выключено — у плагина кнопка «Установить» (при открытом Revit — «Установить при закрытии»).

### 8.5. Настройки (вкладка «Плагины Revit»)

- Обновлять автоматически (вкл. по умолчанию); сообщать, когда установлены.
- «Сборки: Рабочие / Пробные» — переключатель виден только назначенным испытателям. **[Решение 25.10]** Список ведут администратор и BIM-менеджер в Teams.

### 8.6. Журнал

- Каждая проверка, загрузка, установка, откат — строка: плагин, версии, результат, причина ошибки.

## 9. Учёт времени: «Начать работу / Закончить работу»

**[Решение 25.10]** Остаётся в приложении (В1). Без изменений против v2.

### 9.1. Где хранится

- **[Решение]** Таймер хранится **на сервере Teams** (0.10.0): один на пользователя, виден на сайте, в приложении и на втором компьютере. Приложение получает состояние через API и сокет и управляет им через API таймера.
- Записи в трудозатраты — обычные записи Teams (`POST /api/time`), со всеми проверками: только свои задачи, без пересечений, не позже сегодня.

### 9.2. Начать (v1, Д-В-0…3)

- **Откуда:** меню трея «▶ Начать работу…»; кнопка «▶ Начать работу» в уведомлении о назначенной задаче и под карточкой служебного чата; на сайте — верхняя панель и «Моя страница».
- **Окно выбора задачи:** поиск по марке, названию, объекту; группы «Недавние» (3 последние), затем по объектам; источник — `GET /api/time/options`; «Время пойдёт с 09:05»; двойной щелчок или «▶ Начать».
- Если таймер идёт на другой задаче — «Записать и сменить»: сначала «Закончить работу» по текущей, после записи — старт новой.

### 9.3. Закончить (v1, Д-В-4)

- **Окно «Записать в трудозатраты».** Вверху — фактическое время и интервалы, ниже строки записей.
- **[Решение] Округление:** начало и конец каждого интервала — до ближайших :00 или :30. Интервал, ставший нулевым (меньше 15 минут работы), не записывается.
- Соседние интервалы одной задачи после округления склеиваются.
- В каждой строке «с» и «до» можно поправить (список по 30 минут), строку можно убрать; общее примечание.
- **Пересечение с уже записанным временем** — ошибка сервера у строки, остальные строки не записываются, пока не исправлено.
- **Кнопки:** «Записать»; «Продолжить работу»; «Сбросить без записи» — с подтверждением.

### 9.4. Пауза при блокировке (v1, Д-В-8)

- **[Решение]** Блокировка, заставка, сон, выключение — таймер **сам встаёт на паузу** с причиной «компьютер заблокирован» (`powerMonitor`: `lock-screen`, `suspend`, `shutdown`).
- Пауза ставится **временем события**. Нет связи — команда ждёт в очереди и уходит при появлении связи.
- После разблокировки — уведомление «Таймер на паузе. Компьютер был заблокирован 12:40–13:30, это время не учтено. АР1 · 2:10» с кнопками «▶ Продолжить» и «■ Закончить работу».
- **[Предложение Claude]** Настройка «После разблокировки спросить «Продолжить?»».
- Обе настройки — на этом компьютере.

### 9.5. Конец дня (v1, Д-В-5, Д-В-7)

- **[Решение]** Напоминание в 18:30 (время — в настройках), если таймер идёт: «Таймер ещё идёт · АР1 · 7:20 с 09:05», кнопки «■ Закончить работу», «Ещё работаю».
- **[Решение]** Полночь — таймер останавливает **сервер**. Записи — до конца рабочего дня бюро с пометкой «проверить». Конец рабочего дня — из настроек бюро, в приложении только для чтения.
- Утром — уведомление «Вчерашний таймер остановлен в полночь · АР3: записано до 18:00 с пометкой «проверить»» с кнопкой «Проверить запись ↗» (сайт, «Трудозатраты»).

### 9.6. Без связи

- Таймер идёт на сервере. Команды без связи ждут в очереди со временем события.
- Окно «Закончить работу» без связи не открывается — «Нет связи с сервером, попробуйте позже».

## 10. Новая версия приложения (v1, Д-Н-6)

- **[Решение]** Тихого обновления приложения в 1.0 нет.
- При запуске и раз в 6 часов: `GET /api/desktop/latest` → `{version, notes, url, size, sha256}`.
- Версия новее: полоса в окне «Доступна новая версия приложения 1.1.0 — Скачать и установить · Позже · Что нового»; пункт «⬇ Доступна версия 1.1.0» в меню трея.
- «Скачать и установить»: загрузка с ходом, сверка `sha256` и подписи (та же, что у установленного) → запуск установщика → приложение закрывается.
- «Позже» — до следующего запуска или следующей версии.

## 11. Установка, подпись, первый запуск

### 11.1. Установщик

- **[Решение]** Ставит сам сотрудник, **без прав администратора**: NSIS `perMachine: false`, папка `%LOCALAPPDATA%\Programs\Schema Teams`.
- Регистрация для уведомлений в `HKCU` (5.1) — при установке, стирается при удалении.
- Ярлык в меню «Пуск», без ярлыка на рабочем столе. Удаление — через «Приложения» Windows; журналы и настройки остаются, плагины Revit — тоже (удаляются отдельно).
- **Адрес сервера** зашит в сборку из закрытого `.env` (`SERVER_URL`); в репозитории — `.env.example` с `<SERVER_HOST>`.
- Имя файла с версией: `Schema Teams Setup 1.0.0.exe`, рядом `.md` с коротким списком изменений.

### 11.2. Подпись

- **[Решение]** Сертификат бюро для плагинов («Schema Bureau Revit Plugins»). Ключ `.pfx` — вне репозитория, путь и пароль — из переменных окружения. Подписать установщик и `Schema Teams.exe`.
- Установщик плагинов уже добавляет сертификат в доверенные у пользователя. На компьютерах без плагинов — `import-cert.ps1` из папки плагинов, без прав администратора.
- **[Уверенность низкая]** SmartScreen при первом запуске скачанного файла — проверить на пробной сборке.

### 11.3. Первый запуск

1. «Подключение к Schema Teams»: адрес сервера (из сборки, можно поправить), «Проверить связь» → «✓ Сервер отвечает, версия 0.10.0». Ниже 0.10.0 — дальше не пускать.
2. «Вход» — страница входа Teams в окне.
3. «Плагины Revit»: найденные версии Revit и плагины, «Обновлять автоматически» (вкл.).
4. «Готово»: где искать значок, галочка «Запускать вместе с Windows», совет включить значок в «Параметры → Панель задач → Значки в углу».

## 16. Приёмка

Страница приёмки `<дата> — Приёмка Desktop 1.0.html`, сценарии:

1. Установка без прав администратора, первый запуск, вход; перезагрузка Windows — приложение в трее, пароль не спрошен.
2. Окно закрыто ✕ — сообщение в личный чат → уведомление; быстрый ответ «Отправить» дошёл, в чате видно; повторное нажатие не дублирует сообщение.
3. Сообщение в групповом чате и в чате объекта; три сообщения подряд → одно уведомление, в центре уведомлений — группа чата.
4. @упоминание при включённом «Фокусе» проходит, обычные сообщения — нет; после фокуса — сводка.
5. Сервер остановлен → значок серый, «Нет связи»; сервер запущен → всё вернулось само, пропущенные сообщения подтянулись.
6. Тема «Тёмная» в настройках → окно и меню трея тёмные; «Как в Windows» следует за системой.
7. Окно: список чатов, переписка, история при прокрутке, отправка текста, картинка из буфера, файл; прочитано отмечается.
8. Фото и файл из чата открываются и скачиваются; реакция ставится и снимается (если есть в API).
9. Служебный чат: карточки событий, «Прочитать все»; «Ответить в чате» открывает чат на сообщении, «Открыть на сайте» — страницу в браузере; «Мои задачи ↗» и «Сайт ↗» — сайт.
10. Путь к папке из чата → Проводник; `.rvt` → Revit; `.bat` → только «Показать в папке»; недоступный путь → «Папка недоступна» через 3 с.
11. Новая проверенная сборка плагина при закрытом Revit → установлена сама, уведомление; Revit видит новую версию в 2025 и 2026.
12. Revit открыт → «Ждёт закрытия Revit», полоса и уведомление; Revit закрыт → установка и «Плагины обновлены».
13. Подпись не совпала или `sha256` другой → не установлено, ошибка в окне и журнале. Пробная сборка у неиспытателя не ставится; у испытателя с «Пробные» — ставится.
14. «Вернуть прошлую версию» → прошлая версия на месте, Revit её видит.
15. Таймер из трея → на сайте то же время; со второго компьютера — тоже.
16. «▶ Начать работу» из уведомления и из служебного чата запускает таймер на задаче.
17. Win+L на 20 минут → пауза с временем блокировки; после входа — «Продолжить?».
18. «Закончить работу» → строки округлены, правка «до», запись в «Трудозатратах»; пересечение → ошибка у строки. Смена задачи при идущем таймере → запись по первой, старт второй.
19. Таймер оставлен на ночь → утром уведомление и запись до конца рабочего дня с пометкой «проверить».
20. Новая версия приложения на сервере → полоса и пункт меню, установка по кнопке, перезапуск новой версией.
21. Утренняя сводка: первая разблокировка после 08:00 в рабочий день — одно уведомление; повторная разблокировка — нет; выключена в настройках — нет.
22. «Сообщить о проблеме»: снимок и выбранные журналы ушли одним сообщением; в журнале приложения нет текстов сообщений.
23. Настройки: текст сообщений, звук, автозапуск, тема — работают после перезапуска.
24. Память: замер рядом с Revit записан в `docs/decisions.md`.
25. Вид сверен с макетом v4 в светлой и тёмной теме: цвета, формы аватаров (люди — круг, объекты — скруглённый квадрат, служебный чат — «капля»), шкала размеров, пиктограммы Phosphor (у выбранной папки — залитая); контраст текста не ниже 4,5:1.
26. Цветные группы: новое упоминание переносит чат в «Ждут вашего ответа», ответ — убирает; чаты объекта с активной задачей — в группе объекта.
27. Реакции: панель по наведению, постановка с анимацией, снятие; с «Уменьшить движение» в Windows — без анимаций и без конфетти.
28. Альбом выдан → карточка с праздником в служебном чате; обычные события — без конфетти.
29. Меню трея: новое сообщение внизу, ответ из меню дошёл и не продублировался; нет непрочитанного — блока нет.
