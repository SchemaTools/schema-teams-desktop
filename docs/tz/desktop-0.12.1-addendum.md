# Изменения задач Desktop для Teams 0.12.1

Сверено 30.10.2026. Это дополнение к ТЗ Desktop v4 и текущий порядок интеграции,
а не отчёт о готовности новой версии приложения.

## Источники и приоритет

1. Решения руководителя в [постановке сервера v5](server-desktop-0.12.1-v5.md),
   в том числе Д1–Д4 от 29.10. Источник —
   [stage/e15, docs/tz/postanovka-0.12.1.md](https://github.com/SchemaTools/schema-teams/blob/stage/e15/docs/tz/postanovka-0.12.1.md),
   blob `c0e29332ff5f2b92d369f511c77a4a7c30d148a8`.
2. Ответы сервера из ветки обмена Desktop, коммит `092107c0352954e8eb3c179f146da6564a9ab685`:
   [чат и бюро](../../tasks/replies/SERVER-CHAT-001.md),
   [таймер](../../tasks/replies/SERVER-D5-001.md),
   [сводка, поддержка и плагины](../../tasks/replies/TEAMS-0.12.1.md).
3. Фактические shared-типы `stage/e15`: `desktop-config.ts` — `6c7bbbfb`,
   `time-timer.ts` — `1d41c38b`, `chat.ts` — `be967d8a`.
   При расхождении примера и реализации сверять DTO/маршрут и фиксировать отличие.

В публичном `/api/health` стенда подтверждена версия **0.12.1**. Авторизованный
`/api/desktop/config` в этом проходе не читался; конкретные capabilities,
выбранный чат поддержки и содержимое реестра ещё не подтверждены клиентом.
Отчёты серверных тестов — сведения исполнителя, не результаты испытания Desktop.

Постановка v5 заменяет прежние SERVER-CHAT-001/SERVER-D5-001 как требования
к серверу. Номера исторических заданий не меняют шаги Desktop: Д5 — плагины,
Д6 — таймер. Серверный репозиторий по-прежнему строго только для чтения.

## Что меняется

| Часть | Было в 0.6.8 / прежнем плане | Требуется теперь |
| --- | --- | --- |
| Возможности сервера | Статические ограничения по 0.11.2-b, нет desktop/config | Читать bureau.timeZone/workEnd, serverNow, supportChatId и версии capabilities после входа. Нет capability — нет функции. |
| Таймер | Собственные окна уже есть; preflight по version/taskId/startedAt перед старым запросом | CAS сервера: expected `{timerId, revision, currentSegmentFrom}` и Idempotency-Key. Preflight не заменяет CAS. |
| Подготовка записи | Старый GET proposal | prepare-finish → prepared/:requestId → validate-rows → finish с новым ключом и preparedRequestId. Никакой скрытой паузы при открытии/закрытии формы. |
| Выбор задачи | time/options и локальные недавние | Новый pick-list с поиском/видимостью сервера; личные задачи и серверные недавние. |
| Автопауза | Отключена из-за отсутствия CAS | Интегрировать только при timerControl >= 2, с исходным снимком и временем по serverNow. Старое событие не действует на новый таймер; автоматического resume нет. |
| Чат | Шесть реакций, нет myActiveTasks/top | Восемь реакций; быстрая панель по ТЗ, прежние laugh/question сохранены. Группы по myActiveTasks, персональное top до пяти чатов. |
| События | Часть новых видов недоступна | album_issued и remarks_closed; kind и notificationId из сокета, без разбора текста. Праздник только у нужного события, reduced motion сохранён. |
| Тихие часы | Консервативное подавление при неизвестном поясе | quiet из chat:message, пояс бюро из config. Догруженная история не превращается в поток popup. |
| Значки интерфейса | Phosphor с двухтоновой заливкой | **Lucide** по решению Д4 от 29.10. Fluent Emoji реакций — отдельные изображения, их это решение не заменяет. |
| Поддержка | Локальный ZIP без доставки | support/files, затем support с тем же ключом при повторе. От имени отправителя, без добавления в участники, до трёх файлов. no_support_chat — явный запасной путь. |
| Утро | Маршрут ожидался от сервера | morning по календарю/дате бюро; одно фактическое уведомление, не локальный подсчёт задач. |
| Плагины | Только обзор стандартных папок | Реальный реестр, tester, stable/beta, зависимости, desktop:plugins. Проверка SHA256 и доверенной подписи DLL остаётся обязанностью Desktop. |
| Ночная остановка | Только событие timer_stopped | pending/ack для устойчивого deviceId. Ack только после фактического показа; чужое устройство не теряет своё уведомление. |

Мост 1.2, capability chatUi, новая схема входа, CORS/Bearer, чат «без звука»
не добавляются. Версия — `/api/health`, не `/api/version`; реальное событие
таймера — `time:timer`. Просмотрщик документов объекта, папки «как в Sarex»
и сравнение PDF вынесены в отдельный стенд; существующие вложения чата сохраняются.

## Порядок реализации и проверка

1. **Основа совместимости.** Строгий разбор config/новых DTO, хранение только в main,
   сброс по epoch при смене входа/сервера, capability gate. Проверки: отсутствие,
   неизвестная версия и некорректные поля, старый сервер, поздний ответ другого входа.
2. **Таймер — первым функциональным блоком.** Все изменяющие запросы с expected
   и устойчивым ключом операции. Затем новая подготовка/проверка строк, pick-list,
   pending/ack и безопасная автопауза. Проверки: таймер A не меняет B, повтор finish
   после старта B, потерянный ответ, одинаковые параллельные запросы, ошибки по строкам.
   409/428/400/403 автоматически не повторять; сетевой повтор — тем же ключом/телом.
3. **Д4.** Новые поля групп/закрепления, реакции и события, quiet. Проверки:
   шестой top, права, неизвестный вид, reconnect без popup-дублей и reduced motion.
4. **Lucide.** Перенести общие значки main/tray/форм, сохранить согласованные размеры,
   клавиатуру, подписи и доступность; повторить контраст двух тем. Существующие окна
   таймера сохраняют свой интерфейс. Если меняется отсутствующий в макете вид формы,
   сначала подготовить конкретный макет для согласования.
5. **Д7.** Поддержка и morning: неизменяемый предпросмотр → загрузка → одно сообщение,
   неизвестный исход/повтор без дубля, отсутствие чата; выходной, повторная разблокировка,
   политика показа и сохранение дня только после показа.
6. **Д5.** Каталог и каналы, загрузка с лимитами/хешем, подпись, зависимости,
   ожидание закрытия Revit, атомарная установка и откат. Отсутствие доверенного
   сертификата/проверенных сборок остаётся реальным ограничением установки.

Сборка **0.6.8** ещё не реализует эти договоры. Её 569/114 тестов относятся
к прежним фикстурам; они не подтверждают совместимость таймера с 0.12.1.
Приёмку по старому сценарию нельзя автоматически переносить на новую интеграцию.
Новый установщик и новые строки единой Excel-книги выпускать после проверенного
клиентского блока. Все прежние факты сохранять. Реальные команды таймера,
сообщения поддержки и установки плагинов на стенде в этом проходе не выполнялись.

Сохраняются прямые указания пользователя: Enter отправляет, Shift+Enter переносит
строку; UNC — «Показать в папке». Почасовая серия закончена; проверка нового ТЗ
не возобновляет планировщик.
