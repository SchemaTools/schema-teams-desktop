## 1. Что это и границы

Настольное приложение Schema Teams для Windows 10/11 на компьютерах бюро. Живёт в трее, показывает веб-интерфейс Teams в своём окне и даёт то, чего не может браузер на HTTP-странице: уведомления Windows, открытие сетевых папок, кнопки учёта времени рядом с часами.

### 1.1. Состав 1.0

| № | Функция | Раздел |
|---|---|---|
| 1 | Трей со счётчиком и меню, окно Teams, автозапуск | 4 |
| 2 | Уведомления Windows: сообщения, @упоминания, задачи; учёт «Фокуса» и тихих часов | 5 |
| 3 | Быстрый ответ из уведомления | 5.4 |
| 4 | Открытие путей `\\сервер\…` из чата и карточек | 6 |
| 5 | «Начать работу / Закончить работу» — таймер для трудозатрат | 7 |
| 6 | «Есть новая версия — скачать» | 8 |
| 7 | Установщик без прав администратора, подпись, первый запуск, настройки, журналы | 9–11 |

### 1.2. Не входит в 1.0

- **[Решение]** Тихое автообновление — перенесено. В 1.0 только проверка версии и установка по кнопке (раздел 8).
- **[Решение]** «Отметить обед» из уведомления — позже.
- **[Решение]** Автообновление плагинов Revit (Schema.Tools) — отдельным этапом этого же проекта.
- Телефон, macOS, работа без офисной сети через интернет.

## 2. Устройство

### 2.1. Стек

- **[Решение]** Electron, только Windows 10/11 x64.
- **[Предложение Claude]** TypeScript `strict`; сборка — `electron-builder` (MIT), установщик NSIS; тесты — Vitest (логика главного процесса) и Playwright `_electron` (сквозные, против заглушки сервера).
- **[Решение] Лицензии.** Пакет `electron` — MIT, в поставке Electron есть `ffmpeg.dll` под LGPL-2.1 (отдельная динамическая библиотека, не изменяется). Для настольного приложения — **исключение из правила лицензий бюро**: приложение внутреннее и отдельно не продаётся (решение руководителя 16.10.2026, `docs/decisions.md`). Других зависимостей под LGPL/GPL не добавлять.

### 2.2. Главная мысль: приложение — тонкая оболочка

**[Предложение Claude, принято руководителем]**

- **Окно** показывает обычный веб-интерфейс Teams с сервера (`BrowserWindow`, адрес из настроек).
- **Вход** — обычная страница входа Teams. Cookie сессии хранятся в постоянном разделе (`session.fromPartition('persist:teams')`). Пароль спрашивается один раз; сессия гаснет через 14 дней без активности, как в браузере.
- **Соединение реального времени** (Socket.IO) держит сама страница Teams, приложение своего соединения не открывает.
- **✕ окна** только прячет окно, страница продолжает жить. Поэтому у окна `backgroundThrottling: false`.
- **Мост.** Страница сообщает приложению события (счётчики, уведомления, таймер), приложение передаёт странице команды (открыть чат, ответить, запустить таймер). Мост — `preload`-скрипт с `contextBridge` (раздел 3).
- **Вызовы API** делает только страница: у приложения нет логина, пароля, токена и CSRF-ключа. Например, быстрый ответ — команда странице «отправь текст в чат N», страница шлёт запрос своим клиентом API.

Плюс: логика уведомлений, прав и таймера живёт в Teams и проверяется там; приложение почти не меняется при обновлениях сервера.

### 2.3. Окна приложения

| Окно | Что внутри | Код макета |
|---|---|---|
| Главное | веб Teams, вся страница | Д-О-1 |
| Выбор задачи, «Закончить работу» | страницы Teams `/desktop/pick` и `/desktop/finish` (0.10.0) в маленьком окне без рамки у трея, тот же раздел cookie | Д-В-3, Д-В-4 |
| Настройки, первый запуск | локальная страница приложения | Д-Н-1, Д-Н-8 |
| Меню трея | своё окно без рамки (не системное меню) — в нём таймер и счётчики | Д-Т-2 |
| Уведомления | см. 5.1 | Д-У-* |

### 2.4. Безопасность

- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false` во всех окнах с содержимым сервера.
- **Мост выдаётся только странице с адресом сервера из настроек** (сверка `origin` в preload и в главном процессе на каждый вызов).
- Переходы внутри главного окна — только в пределах адреса сервера. Остальные ссылки — в браузер по умолчанию (`shell.openExternal`, только `http`/`https`).
- Не открывать новые окна со страницы (`setWindowOpenHandler` → внешний браузер или запрет).
- Открытие путей — по правилам раздела 6, никаких произвольных команд.
- Один экземпляр (`requestSingleInstanceLock`); повторный запуск показывает окно.

## 3. Мост

Договор — один файл типов `src/bridge/protocol.ts`, общий с `schema-teams` (копия с номером версии протокола). При несовпадении старшей версии приложение показывает полосу «Приложение устарело — обновите» и работает только как окно.

### 3.1. Страница → приложение (события)

| Событие | Данные | Что делает приложение |
|---|---|---|
| `hello` | версия протокола, пользователь (id, «Фамилия И.О.»), версия сервера | связь установлена; до `hello` — значок «нет связи» |
| `signedOut` | — | счётчик пуст, меню «Войти», уведомлений нет |
| `counters` | `{chat, notifications}` | число на значке трея и панели задач |
| `notify` | вид, заголовок, текст, автор, ссылка, чат и сообщение (для ответа), кнопки | показать уведомление (раздел 5) |
| `timer` | `{state: idle/run/pause, task {id, mark, title}, startedAt, elapsedSec, reason}` | значок и меню трея, напоминание (7.5) |
| `focus` | `{until}` или `null` | луна на значке, пункт меню |
| `connection` | `online` / `offline` | серый значок и «!», подсказка (Д-С-1) |
| `openPath` | путь, `{reveal}` | раздел 6, ответ странице: `ok` / `unavailable` / `blocked` |

### 3.2. Приложение → страница (команды)

| Команда | Что делает страница |
|---|---|
| `navigate(link)` | переход по ссылке Teams (`/chat/<id>?m=<id>`, `/albums/<id>` …) |
| `reply(chatId, text)` | отправить сообщение, ответ `ok` или текст ошибки |
| `markRead(kind, id)` | прочитано (чат до сообщения или уведомление) |
| `timer(action, {taskId, at})` | `start` / `pause` / `resume` / `stop` — через API таймера (0.10.0) |
| `focus(until или null)` | включить или завершить «Фокус» |
| `windowState({visible, focused})` | страница учитывает при решении, показывать ли уведомление (5.2) |

Все команды идемпотентны по `requestId`: повтор после обрыва не дублирует сообщение и запись.

## 4. Окно и трей

### 4.1. Значок в трее (Д-Т-1)

- Знак Schema 16×16 (светлая и тёмная панель задач) — рисуется на лету.
- **Состояния:**
  - число непрочитанного (чат + колокольчик), больше 9 — «9+»;
  - точка таймера: зелёная — идёт, янтарная — пауза;
  - луна — «Фокус»;
  - серый знак с «!» — нет связи.
- Подсказка при наведении — 2–4 строки: непрочитанное, таймер «▶ АР1 · 1:12», «Фокус до 15:00», «Нет связи».
- **Щелчок** — показать или спрятать окно. **Правая кнопка** — меню (4.2).
- Значок на панели задач — с наложенным счётчиком (`setOverlayIcon`), пока окно открыто (Д-Т-5).

### 4.2. Меню значка (Д-Т-2, Д-Т-3)

Своё окно без рамки над треем, тёмное, как в макете:

1. Шапка: «Фамилия И.О.» и состояние («в сети», «в фокусе до …», «нет связи»).
2. **Таймер.** Если не идёт — «▶ Начать работу…» с последней задачей справа. Если идёт или на паузе — блок: задача, время, «с 09:05», кнопки «Пауза / Продолжить», «Сменить», «Закончить».
3. «Чат N», «Уведомления N».
4. «☾ Фокус ›»: 30 минут, 1 час, до 15:00, до конца дня; при фокусе — «Завершить фокус».
5. «Открыть Schema Teams», «Настройки…», «⬇ Доступна версия …» (если есть).
6. «Выход» и номер версии.

Меню закрывается щелчком вне его и клавишей Esc.

### 4.3. Окно (Д-О-1…3)

- Обычная рамка Windows, заголовок «Schema Teams». Размер и положение запоминаются, с поправкой, если монитор отключили.
- **✕ и «Свернуть»** — окно прячется в трей. При первом закрытии — уведомление «Schema Teams работает в трее. Уведомления будут приходить. Выйти совсем — правой кнопкой по значку → «Выход»» (Д-О-3).
- Полосы над страницей рисует приложение: «Доступна новая версия» (Д-Н-6). «Нет связи» рисует сам веб Teams (уже есть).
- Горячих клавиш нет. Масштаб страницы Ctrl+колесо — как в браузере, запоминается.

### 4.4. Автозапуск (Д-Н-2)

- **[Решение]** Включён по умолчанию, отключается в настройках (`app.setLoginItemSettings`, ключ `--hidden`).
- При автозапуске окно не показывается, только значок.

## 5. Уведомления

### 5.1. Чем показывать

Быстрый ответ в родных уведомлениях Windows требует `toastXml` с полем ввода и обработки активации. В Electron 44 поле ответа, кнопки и `Notification.handleActivation` есть и на Windows (правка 22.10: прежняя пометка «`reply` только на macOS» устарела). На Windows 10 нужны регистрация приложения установщиком и постоянный код активатора — `docs/decisions.md`, 22.10.2026.

**Первый шаг раздела — опыт на одном ПК с Windows 10 и одном с Windows 11.** Родное уведомление с полем ответа и двумя кнопками, ответ доходит до приложения при открытом и при спрятанном окне.

- **Работает** → родные уведомления: попадают в центр уведомлений и подчиняются «Не беспокоить» Windows.
- **Не работает** → свои окна без рамки в правом нижнем углу над треем, вид — как в макете (Д-У-0): стопка до 3, новые снизу, через 8 с уходят, пока на них мышь или идёт ввод — держатся. Тогда в центре уведомлений Windows их нет — записать в `docs/decisions.md`.

Результат опыта — в `docs/decisions.md` до начала остальной работы раздела.

### 5.2. Когда показывать

Решает **страница** (там правила Teams), приложение только показывает. Страница отправляет `notify`, если выполнены все условия:

1. Событие сокета: `notification` (без `quiet`), `chat:message` (не своё), `chat_mention`.
2. «Фокус»: пока включён, проходят только @упоминания (решение 0.9.0). Остальное копится; после фокуса — одно уведомление «Пока вы были в фокусе: N сообщ. в M чатах, упоминаний K» с кнопкой «Открыть чат» (Д-Ф-2).
3. Тихие часы и выбор событий — из настроек уведомлений пользователя в Teams (флаг `quiet` сервера). **В приложении эти настройки не дублируются**, в окне настроек — ссылка на них (Д-Н-4).
4. Не показывать, если окно видно и в фокусе, а пользователь уже смотрит этот чат или эту задачу.
5. Чат «без звука» — если такой признак появится в Teams, учитывать.

### 5.3. Виды (Д-У-1…3)

| Вид | Заголовок | Текст | Кнопки |
|---|---|---|---|
| Сообщение в личном чате | Фамилия И.О. | текст | поле «Ответить…», «Открыть», «Прочитано» |
| Сообщение в группе или чате объекта | название чата | «Фамилия И.О.: текст» | то же |
| @упоминание | «Фамилия И.О. упомянул вас · чат» | текст | то же |
| Назначена задача | «Вам назначен альбом АР3 «Разрезы»» | объект, срок, кто назначил | «Открыть», «▶ Начать работу» |
| Прочие уведомления колокольчика | как строка колокольчика Teams | «было → стало» | «Открыть» |

- Несколько сообщений одного чата за минуту — одно уведомление «3 новых сообщения» с последним текстом.
- Настройка «Показывать текст сообщения» выключена — «Новое сообщение» без текста.
- Звук — системный звук уведомления, отключается в настройках.
- Щелчок по уведомлению — как «Открыть»: окно на передний план и `navigate(link)`.

### 5.4. Быстрый ответ

- Enter или «➤» → `reply(chatId, text)` → уведомление закрывается, короткое «Отправлено в «чат»».
- Ошибка (нет связи, исключён из чата) — уведомление остаётся, текст под полем: «Не отправлено: …», введённый текст не теряется.
- В чате у такого сообщения особой пометки нет. **[Предложение Claude]**: в макете «ответ из уведомления» — только подпись для наглядности.

## 6. Сетевые пути

### 6.1. Откуда

Веб Teams 0.9.0 превращает путь `\\сервер\…` в чате в карточку с «Скопировать путь». В приложении у карточки появляются «Открыть» и, для файла, «Показать в папке» (Д-П-1, Д-П-2). Решение показывать кнопки принимает страница по наличию моста.

### 6.2. Правила открытия

- Принимаются только пути UNC вида `\\server\share\…`. Без `..`, без `file://`, без букв дисков и без адресов устройств Windows (начинаются с «\\?» или «\\.»).
- **Папка** — `shell.openPath` → Проводник под правами сотрудника (Д-П-3).
- **Файл** — открыть в программе по умолчанию. Исключение — исполняемые и скрипты (`exe, msi, bat, cmd, com, scr, ps1, vbs, vbe, js, jse, wsf, hta, lnk, reg, cpl, jar`): для них только «Показать в папке» (`shell.showItemInFolder`), а странице ответ `blocked` с текстом «Такие файлы не открываются из Teams — только папка с ним».
- **Проверка доступности** — `fs.stat` с тайм-аутом 3 с (сетевые пути зависают). Нет ответа или ошибка → окно «Папка недоступна» с путём, пояснением «нет доступа, сервер выключен или вы не в офисной сети», кнопками «Скопировать путь» и «Понятно» (Д-П-4).
- Каждое открытие — строка в журнале приложения (путь, результат), без содержимого.

### 6.3. Не проверено

- **[Уверенность низкая]** Все ли компьютеры видят папки сервера бюро под своими учётными записями — проверить на пробной сборке (раздел 12).

## 7. Учёт времени: «Начать работу / Закончить работу»

### 7.1. Где хранится

- **[Решение]** Таймер хранится **на сервере Teams** (0.10.0): один на пользователя, виден в вебе, в приложении и на втором компьютере. Приложение показывает его по событию `timer` и управляет командами `timer(...)`.
- Записи в трудозатраты — обычные записи Teams (`POST /api/time`), со всеми проверками: только свои задачи, без пересечений, не позже сегодня.

### 7.2. Начать (Д-В-0…3)

- **Откуда:**
  - меню трея «▶ Начать работу…»;
  - верхняя панель Teams «▶ Начать работу»;
  - «▶ Начать» у задачи на «Моей странице»;
  - кнопка «▶ Начать работу» в уведомлении о назначенной задаче.
- **Окно выбора задачи** (Д-В-3):
  - поиск по марке, названию, объекту;
  - группы: «Недавние» (3 последние), затем по объектам;
  - источник — `GET /api/time/options` (мои активные альбомы и подзадачи);
  - текст «Время пойдёт с 09:05»;
  - двойной щелчок или «▶ Начать».
- Если таймер уже идёт на другой задаче — «Записать и сменить»: сначала окно «Закончить работу» по текущей, после записи — старт новой.

### 7.3. Закончить (Д-В-4)

- **Окно «Записать в трудозатраты».** Вверху — фактическое время и интервалы, ниже строки записей.
- **[Решение] Округление:** начало и конец каждого интервала — до ближайших :00 или :30 (в Teams часы кратны 0,5). Интервал, ставший нулевым (меньше 15 минут работы), не записывается.
- Соседние интервалы одной задачи после округления склеиваются.
- В каждой строке «с» и «до» можно поправить (список по 30 минут), строку можно убрать; общее примечание.
- **Пересечение с уже записанным временем** — ошибка сервера показывается у строки («На это время уже есть запись: 10:00–11:00, АР2»), остальные строки не записываются, пока не исправлено.
- **Кнопки:**
  - «Записать» — записи созданы, таймер сброшен;
  - «Продолжить работу» — закрыть окно, таймер идёт;
  - «Сбросить без записи» — с подтверждением.

### 7.4. Пауза при блокировке (Д-В-8)

- **[Решение]** Блокировка (Win+L), заставка, сон, выключение — таймер **сам встаёт на паузу** с причиной «компьютер заблокирован» (`powerMonitor`: `lock-screen`, `suspend`, `shutdown`).
- Пауза ставится **временем события**, а не временем, когда дошла команда (`at` в команде). Если связи нет — команда ждёт в очереди и уходит при появлении связи.
- После разблокировки — уведомление «Таймер на паузе. Компьютер был заблокирован 12:40–13:30, это время не учтено. АР1 · 2:10» с кнопками «▶ Продолжить» и «■ Закончить работу».
- **[Предложение Claude]** Настройка «После разблокировки спросить «Продолжить?»». Выключена — таймер стоит на паузе молча до «▶».
- Обе настройки (пауза и вопрос) — **на этом компьютере**, в приложении.

### 7.5. Конец дня (Д-В-5, Д-В-7)

- **[Решение]** **Напоминание** в 18:30 (время — в настройках приложения), если таймер идёт: «Таймер ещё идёт · АР1 · 7:20 с 09:05», кнопки «■ Закончить работу», «Ещё работаю». Показывает приложение.
- **[Решение]** **Полночь** — таймер останавливает **сервер** (работает и при выключенном компьютере). Записи — до конца рабочего дня с пометкой «проверить».
  - **[Предложение Claude]** Конец рабочего дня берётся из настроек бюро (`workday.end`). В макете поле в настройках приложения редактируемое — по ТЗ оно **только для чтения**: «Конец рабочего дня бюро: 18:00».
- Утром — уведомление «Вчерашний таймер остановлен в полночь · АР3: записано до 18:00 с пометкой «проверить»» с кнопкой «Проверить запись» → «Трудозатраты».

### 7.6. Без связи

- Таймер идёт на сервере, связь ему не нужна. Команды, поданные без связи (пауза при блокировке, «Закончить»), ждут в очереди со временем события.
- Окно «Закончить работу» без связи не открывается — «Нет связи с сервером, попробуйте позже».

## 8. Новая версия (Д-Н-6)

- **[Решение]** Тихого обновления в 1.0 нет.
- При запуске и раз в 6 часов: `GET /api/desktop/latest` → `{version, notes, url, size, sha256}` (0.10.0).
- Версия новее установленной:
  - полоса в окне «Доступна новая версия приложения 1.1.0 — Скачать и установить · Позже · Что нового»;
  - пункт «⬇ Доступна версия 1.1.0» в меню трея.
- «Скачать и установить»: загрузка во временную папку с ходом загрузки, сверка `sha256` → запуск установщика → приложение закрывается. Таймер на сервере не страдает.
- «Позже» — до следующего запуска или следующей версии.
- Сверка подписи скачанного файла: та же подпись, что у установленного приложения, иначе не запускать.

## 9. Установка, подпись, первый запуск

### 9.1. Установщик

- **[Решение]** Ставит сам сотрудник, **без прав администратора**: NSIS `perMachine: false`, папка `%LOCALAPPDATA%\Programs\Schema Teams`.
- Ярлык в меню «Пуск», без ярлыка на рабочем столе. Удаление — через «Приложения» Windows; журналы и настройки при удалении остаются.
- **Адрес сервера** зашит в сборку из закрытого `.env` (`SERVER_URL`); в репозитории — `.env.example` с `<SERVER_HOST>`.
- Имя файла с версией: `Schema Teams Setup 1.0.0.exe`, рядом `.md` с коротким списком изменений (как у плагинов).

### 9.2. Подпись

- **[Решение]** Сертификат бюро для плагинов («Schema Bureau Revit Plugins»). Ключ `.pfx` — вне репозитория, путь и пароль — из переменных окружения на компьютере сборки. Подписать установщик и `Schema Teams.exe`.
- Установщик плагинов уже добавляет сертификат в доверенные у пользователя. На компьютерах без плагинов — `import-cert.ps1` из папки плагинов, без прав администратора.
- **[Уверенность низкая]** SmartScreen может предупреждать при первом запуске скачанного файла и с этой подписью — самоподписанный сертификат не даёт «репутации». Проверить на пробной сборке, вывод — в `docs/decisions.md` и в инструкцию установки.

### 9.3. Первый запуск (Д-Н-8)

1. «Подключение к Schema Teams»: адрес сервера (из сборки, можно поправить), «Проверить связь» → «✓ Сервер отвечает, версия 0.10.0». Версия сервера ниже 0.10.0 → «Нужен Schema Teams 0.10.0 или новее», дальше не пускать.
2. «Вход» — страница входа Teams в окне.
3. «Готово»: где искать значок, галочка «Запускать вместе с Windows», совет включить значок в «Параметры → Панель задач → Значки в углу».

## 10. Настройки (Д-Н-1…5, 7)

## 11. Журналы и «Сообщить о проблеме»

- Журнал: `%APPDATA%\Schema Teams\logs\`, 5 файлов по 1 МБ по кругу.
- Пишутся запуск, версии, связь, события моста (вид, без текста сообщений), открытие путей, команды таймера, ошибки.
- **Не пишутся** тексты сообщений, пароли, cookie.
- «Сообщить о проблеме» — открыть форму обратной связи Teams в окне и папку журналов рядом, как в плагинах бюро. Приложить файл журнала — если форма Teams это позволяет (она принимает файлы и снимок).

## 13. Приёмка

Страница приёмки `<дата> — Приёмка Desktop 1.0.html`, сценарии:

1. Установка без прав администратора, первый запуск, вход; перезагрузка Windows — приложение в трее, пароль не спрошен.
2. Окно закрыто ✕ — сообщение в личный чат → уведомление; быстрый ответ дошёл, в чате видно.
3. Сообщение в групповом чате и в чате объекта; три сообщения подряд → одно уведомление.
4. @упоминание при включённом «Фокусе» проходит, обычные сообщения — нет; после фокуса — сводка.
5. Назначена задача → «▶ Начать работу» из уведомления запускает таймер на ней.
6. Сервер остановлен → значок серый, «Нет связи»; сервер запущен → всё вернулось само.
7. Путь к папке из чата → Проводник; путь к файлу `.rvt` → открывается Revit; `.bat` → только «Показать в папке».
8. Недоступный путь → окно «Папка недоступна» через 3 с, приложение не зависло.
9. Таймер из трея → в вебе Teams видно то же время; со второго компьютера — тоже.
10. Win+L на 20 минут → пауза с временем блокировки; после входа — «Продолжить?».
11. «Закончить работу» → строки округлены, правка «до», запись в «Трудозатратах»; пересечение с существующей записью → ошибка у строки.
12. Смена задачи при идущем таймере → запись по первой, старт второй.
13. Таймер оставлен на ночь → утром уведомление и запись до конца рабочего дня с пометкой «проверить».
14. Новая версия на сервере → полоса и пункт меню, установка по кнопке, приложение перезапустилось новой версией.
15. Настройки: выключить текст сообщений, звук, автозапуск — работает после перезапуска.
16. «Сообщить о проблеме» и «Открыть папку журналов»; в журнале нет текстов сообщений.
17. Память: замер рядом с Revit записан в `docs/decisions.md`.
