# Д4 — открытие сетевых путей

27.10.2026, ветка `codex/d4-paths`, пробная версия **0.2.0**, основа — исправленная
Д3 0.1.1 (`e1b6fa8`). Руководитель разрешил продолжать разработку параллельно
пользовательским проверкам Д3. Windows 11 и пилот не объявляются пройденными.

## Поведение

- `openPath({path,reveal})` использует неизменённый серверный договор 1.1. Проверка
  окна, origin, главного фрейма, hello и данных выполняется до обращения к сервису.
- Только UNC с именем сервера и share. Device namespace, drive/file URL, `.`/`..`,
  пустые компоненты, ADS/двоеточия, управляющие символы, завершающие пробелы/точки,
  DOS-устройства и нефайловые IPC$/PIPE/MAILSLOT отвергаются до I/O.
- Не выполняются trim/decode или общая нормализация. Один завершающий разделитель
  папки убирается; неоднозначные проценты и WebDAV-псевдохосты с @ не принимаются.
  Это намеренное ограничение пробной версии, а не изменение серверных данных.
- Доступная папка или обычный файл открываются через `shell.openPath` под правами
  сотрудника. Явное «Показать в папке» вызывает только `showItemInFolder`.
- Все 17 расширений ТЗ 6.2, дополнительные ярлыки, установщики и известные скрипты
  показываются только в папке. Полный список — `paths/validate.ts`. Файлы без
  расширения тоже не запускаются. Опасный суффикс проверяется и у папки: это
  защищает от подмены её файлом между stat и Shell. Обычные папки без расширения
  открываются нормально.
- По опасному «Открыть» возвращается `blocked`, даже если Проводник показал файл.
  Проверенная страница Teams уже выводит текст «Такие файлы не открываются из
  Teams — только папка с ним». На явный reveal возвращается `ok`.
- Недоступный путь возвращает `unavailable`. Приложение показывает «Папка
  недоступна», путь, объяснение из макета, «Скопировать путь» и «Понятно»; Esc
  закрывает. Страница не должна создавать второй диалог.
- Диалог локальный, sandbox/contextIsolation, без Node и серверного моста, с CSP,
  escaping и запретом навигации/новых окон. IPC копирования проверяет окно, фрейм
  и точный URL. Копирование ждёт результата Clipboard API Electron.
- Повтор одного запроса, пока он выполняется, объединяется. Выход/смена входа,
  навигация и уничтожение приложения отменяют ожидания и старый диалог: поздний
  результат не открывает путь от прежней сессии.
- В локальный журнал записывается валидный путь и результат; сырые OS-исключения
  и содержимое файлов не записываются. Негодная строка в журнал не копируется.

## Сетевой тайм-аут

`fs.stat` работает в отдельном Electron utility process. Через **3 секунды**, с
учётом запуска, parent завершает ожидание и убивает свой процесс. Зависший SMB
не занимает общий файловый пул main. Не более двух живых проверок; слот остаётся
занятым до подтверждённого exit даже при неудачном kill. Отмена до spawn повторяет
завершение после spawn. Неизвестные ответы, ошибки и переполнение дают unavailable.
Никаких shell-команд или аргументов запуска из содержимого страницы нет.

Пример parentPort сверялся с первичной документацией Electron 44.9.1 через
Context7 (точная 44.7.2 там не предлагалась). Типы и реальный запуск/завершение
utility process проверяются на установленной **Electron 44.7.2**.

## Проверки

Автотесты используют локальную страницу, фиктивные UNC `server/share` и перехваты
ОС-действий. Настоящие сетевые папки, Revit и пользовательские файлы из тестов
не открываются. Отдельно запускается настоящий зависший utility worker: main
остаётся доступен, процесс завершается по пределу 3 с. Настоящий statWorker
отвергает локальный путь без обращения к файловой системе.

Ручные сценарии 7–8 ТЗ остаются для Windows 10/11: настоящий UNC-каталог, `.rvt`,
reveal, безопасный тестовый скрипт, отказ доступа/сети и диалог. Для этого создан
новый отдельный Excel с 7 проверками, все «Не проверено». Д3 и серверный репозиторий
не изменяются при заполнении этого бланка.

| Проверка 27.10.2026 | Итог |
|---|---|
| Полный check на чистом снимке | Типы, ESLint, Prettier, 166 модульных и 37 сквозных тестов пройдены |
| Первый полный прогон | 35/37: два сбоя прежних проверок размещения popup на нескольких мониторах; новое окно теперь создаётся сразу в целевой рабочей области, итоговый полный прогон прошёл |
| Настоящий utility process | Зависший fixture завершён по пределу 3 с; main отвечает; worker отвергает локальный путь |
| Локальный диалог | Esc, копирование и изоляция проверены, снимок просмотрен |
| Настоящие UNC/Explorer/Revit и Windows 11 | Не засчитывались; ожидаются ручные результаты |

Протокол и исходники серверной карточки читались только через GET на закреплённом
commit `2589483a58b2c89be98db85ac1e7dc2782f995ad`. Никаких изменений сервера нет.
