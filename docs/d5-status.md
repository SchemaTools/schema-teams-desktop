# Д5 — клиентская часть таймера

28.10.2026, ветка `codex/d5-timer`, пробная версия **0.3.0**, основа — Д4 0.2.0.
Этап Д5 целиком не завершён. Ответ на серверное задание
[SERVER-D5-001](https://github.com/SchemaTools/schema-teams-desktop/blob/codex/task-exchange/tasks/SERVER-D5-001.md)
на момент проверки в ветке обмена отсутствует. Сервер остаётся только для чтения;
договор 1.1 скопирован без изменений. Никаких миграций или серверного выпуска нет.

## Что реализовано

- Уже существующие ручные команды таймера и серверные страницы выбора/завершения
  сохранены. Клиент не рассчитывает округление и не создаёт трудозатраты сам.
- Вечернее напоминание, по умолчанию 18:30 по местному времени компьютера,
  появляется при готовом соединении и идущем таймере. Можно выбрать любое время
  с шагом 30 минут в отдельном окне «Настройки учёта времени…» из меню трея.
- «Ещё работаю» закрывает напоминание. «Закончить работу» после явного нажатия
  проверяет актуальность локального таймера и открывает существующую серверную
  форму; сама кнопка не записывает время и не посылает stop.
- Учитываются настройки всплывающих уведомлений, звука, фокус Teams и системная
  политика Windows. Отказ показа не считается показом; следующая попытка через
  минуту, пока тот же календарный день и таймер ещё идёт. После фактического
  показа — максимум одно напоминание пользователю за день в этой сессии приложения,
  включая переподключения. После полного перезапуска оно может появиться снова.
- События lock/unlock и suspend/resume наблюдаются независимо. Цепочка
  lock → suspend → resume → unlock даёт одно предупреждение после полного
  возврата. Во время отсутствия всплывающие окна скрыты. Выход или смена
  пользователя очищают прежнее предупреждение и старые кнопки.
- При работающем таймере после возврата показывается честное сообщение
  «Автоматическая пауза не подтверждена». В меню предупреждение остаётся до
  «Понятно» или «Проверить таймер», даже если всплывающее окно скрылось.
  Никакого утверждения «это время не учтено» и автоматического resume нет.
- У чата и таймера один общий host уведомлений: общая стопка до трёх окон,
  без наложения; локальные id отделены от ключей сервера. Изменение таймера
  закрывает только устаревшее напоминание и сохраняет черновик ответа в чат.
- Окно настроек локальное, sandbox/contextIsolation/CSP, без Node и серверного
  моста. IPC проверяет окно, главный фрейм, точный URL, форму сообщения и время.
  Сохраняется только время напоминания; остальные настройки сохраняются.
- Исправлено открытие pick/finish: учитывается текущий URL после SPA-перехода.
  Форма того же вида и её черновик сохраняются; другой вид открывается отдельно
  взамен старого окна. Событие idle не закрывает форму: сервер присылает его
  до ответа finish, после которого форма ещё должна запустить следующую задачу.

## Что требует сервера и остаётся открытым

Протокол 1.1 не содержит timerId/revision/currentSegment и не обеспечивает
идемпотентность команд timer. Даже online-пауза может попасть в таймер,
продолженный на другом ПК между локальной проверкой и API. Поэтому до нового
договора **автоматическая пауза выключена**, очередь и повтор команд не создаются.
Это явно написано в меню и настройках; настройки паузы/вопроса показаны
недоступными. Предупреждение не является реализацией автопаузы из ТЗ 7.4.

Без нового сервера также не заявлены: безопасное отложенное завершение, защита
старой формы finish/reset от смены таймера на другом ПК, гарантированное утреннее
уведомление при позднем запуске, часовой пояс и конец рабочего дня бюро.
Последнее поле показывается как «Не передан сервером», без выдуманного значения.
Новый совместимый договор и подтверждение тестов передаёт ответственный за сервер.

## ОС-события и границы проверки

Сверялись первичные исходники [Electron 44.7.2 powerMonitor](https://github.com/electron/electron/blob/v44.7.2/docs/api/power-monitor.md)
и [Chromium 152.0.7977.149 Windows idle](https://github.com/chromium/chromium/blob/152.0.7977.149/ui/base/idle/idle_win.cc).
`getSystemIdleState(1)` применяется только для распознавания locked/unknown;
различие active/idle игнорируется, паузы по порогу бездействия нет.
locked может означать заставку. Начальный WTS-query может вернуть false при
ошибке, поэтому отрицательный ответ не является доказательством разблокировки.
Покрытие заставки на реальной машине отдельно не засчитывалось.

Слушатели регистрируются до первого снимка. После unlock/resume следующий
снимок отложен на следующий оборот event loop: кэш WTS внутри callback ещё
может содержать locked. Явный lock сохраняется до unlock независимо от resume.
unknown/исключение подавляют показ. Проверки повторяются непосредственно перед
показом и после асинхронного запроса Windows. На Windows используется
BrowserWindow `session-end`; powerMonitor `shutdown` там не поддерживается.
Завершение Windows не задерживается, запись таймера при нём не обещается.

## Проверки и ручная приёмка

Автотесты работают с локальной заглушкой и моделируемыми OS-событиями. Они не
блокируют компьютер, не переводят его в сон, не меняют системное «Не беспокоить»
и не управляют настоящим серверным таймером.

| Проверка 28.10.2026 | Результат |
|---|---|
| Полный `npm run check` на чистом снимке index | Типы, ESLint, Prettier, **232 модульных и 47 сквозных тестов** пройдены |
| Настоящий Electron с заглушкой | Настройки сохранены и перечитаны, окна просмотрены; общая стопка не перекрывается, черновик чата сохраняется |
| Гонки | Поздний ответ Windows после lock/logout запрещён; снимок после unlock отложен до обновления WTS-кэша; reset/destroy отменяют callback |
| Серверные формы | pick → finish открывает нужный вид; SPA-переход сохраняет черновик; ранний idle не закрывает finish до startNext |
| NSIS x64 | Установщик 0.3.0 собран, адрес стенда задан только локально, режим опыта выключен; подпись пока отсутствует, как в Д3/Д4 |
| Реальный Win+L/сон, DND, Windows 11 | Не засчитывались; ожидаются ручные результаты |

Чистый снимок исключает посторонние неотслеживаемые локальные проекты; ни одна
проверка или тест не отключались. Перед коммитом проверка обезличенности пройдена.

В промежуточных повторных прогонах два прежних теста малой рабочей области
выявили перенос окон на второй монитор. Одиночные диагностические запуски
воспроизводили его непостоянно; исходная причина переноса Windows не установлена.
Одного повторного layout сразу после show оказалось недостаточно. Теперь
неподвижные окна также возвращаются в целевую стопку по move/resize; сравнение
геометрии учитывает округление DIP до 2 px, а защита от повторного входа исключает
рекурсивный setBounds. Проверки границ не ослаблялись; добавлен отдельный сценарий
принудительного переноса за монитор и возврата в рабочую область. Реальные
многомониторные конфигурации всё равно остаются частью ручной приёмки.

Новый отдельный Excel содержит клиентские сценарии с исходным статусом
«Не проверено» и серверные зависимости со статусом «Блокировано». Неудачный
результат тоже записывается в «Факт»; прежние заполненные таблицы не меняются.
Реальный Win+L, сон/возврат, настройка напоминания и системные режимы ожидают
проверки на Windows 10/11. Полная приёмка сценариев 9–13 ТЗ пока невозможна.

## Уточнение интерфейса чата

28.10 руководитель уточнил, что в приложении нужен собственный экран чата.
В этой сборке пока остаётся веб-чат: она реализует прежний раздел 2.2 ТЗ и не
считается выполнением нового уточнения. Экран чата нарисован в макете v1, а
нынешний мост не передаёт список и историю чатов. Подключение собственного
интерфейса требует отдельного расширения web/shared-договора ответственным
за сервер; приложение не должно извлекать HttpOnly-cookie или переносить
секреты страницы в main. Этот вопрос учитывается до продолжения Д6.

Проект серверной интеграции [SERVER-CHAT-001](https://github.com/SchemaTools/schema-teams-desktop/blob/codex/task-exchange/tasks/SERVER-CHAT-001.md)
размещён в ветке обмена для обсуждения. Руководитель сообщил, что передаст новый
макет: реализация собственного чата будет опираться на него. Старый макет v1
не принят за основу нового экрана, а предварительный объём задания ещё уточняется.
