# Опыт Д2: уведомления Windows с полем ответа — памятка

**Актуально с 23.10:** для требования Enter / Shift+Enter выбран опыт собственных
окон. В новой сборке: «Проверка уведомлений» → «Свои окна: Enter / Shift+Enter».
Родные уведомления оставлены в соседнем подменю для сравнения. Разделы ниже о центре
уведомлений и Ctrl+Enter описывают предыдущие родные сборки; текущий опыт — в конце.

ТЗ, 5.1. Проверяем, работают ли **родные** уведомления Windows с полем ответа и кнопками. Пройти на одном компьютере с Windows 11 и на одном с Windows 10. Время — около 15 минут.

## Подготовка

1. Запустить `Schema Teams Notify Test 0.1.0.exe`. Установка идёт сама, без вопросов; окно приложения покажет «Пробная сборка: проверка уведомлений».
2. Найти значок Schema Teams у часов (квадрат, разделённый по диагонали). Если его не видно — стрелка «^» у часов.
3. Все проверки запускаются так: **правой кнопкой по значку → «Проверка уведомлений» → пункт**.
4. Где отвечать: в поле «Ответить…» внутри уведомления ввести слово **проверка** и нажать Enter (или кнопку отправки рядом с полем).
5. Центр уведомлений: Windows 11 — `Win + N` или щелчок по часам; Windows 10 — `Win + A`.

После каждой проверки записать в таблицу внизу, что увидели. Если что-то пошло не так — это тоже итог, просто записать.

Результат ручной проверки 23.10: Enter в поле ответа переносит строку, а не отправляет
ответ. Это расходится с ТЗ 5.4 («Enter или «➤»»). Отдельной проверкой пользователь
подтвердил: стрелка «Отправить» показывает одно подтверждение «Отправлено…».
Изменение требования об Enter не согласовано.

В [ответе сотрудника Microsoft](https://learn.microsoft.com/en-us/answers/questions/249028/how-to-trigger-buttons-after-typing-something-with)
описано штатное поведение родного toast: Enter — новая строка, Ctrl+Enter — быстрый
ответ, API для переназначения Enter нет. В [схеме action](https://learn.microsoft.com/en-us/uwp/schemas/tiles/toastschema/element-action)
`hint-inputId` связывает кнопку с полем; настройки клавиш нет. Ctrl+Enter на этой
сборке проверен пользователем: появляется одно подтверждение «Отправлено…».
23.10 руководитель отверг замену на Ctrl+Enter: Enter должен отправлять, Shift+Enter —
переносить строку. Для этого выбран опыт собственного окна (ТЗ 5.1, 5.4;
`docs/decisions.md`, 23.10).

Автоматическая визуальная проверка на этом ПК остановлена: оба захвата окна через
computer-use завершились таймаутом (`FrameArrived`, `window capture timed out`).
Дерево элементов читается, но вид уведомлений и нажатия в них не проверены.
Windows 11 в этой сессии недоступна. Д2 остаётся незавершённым до ручных проверок;
окончательное решение по способу уведомлений не принято.

## Текущая сборка: собственное окно, 23.10.2026

После явного требования руководителя **Enter отправляет, Shift+Enter переносит
строку** реализован собственный popup в режиме опыта Д2. Родные уведомления
сохранены в отдельном подменю только для сравнения.

### Что реализовано

- Локальное окно по макету Д-У-0: поле многострочного ответа, кнопка «➤»,
  «Открыть», «Прочитано», закрытие. Показ не забирает фокус у текущей программы.
- Enter отправляет один ответ, Shift+Enter вставляет новую строку; при завершении
  IME-композиции Enter не отправляет незаконченное сообщение. Пустота не отправляется.
- Повторное нажатие до завершения отправки не дублирует действие.
- Без ввода/мыши окно уходит через 8 секунд; при вводе или наведении остаётся.
  Черновик сохраняется и при уходе фокуса, пока окно не закрыто пользователем.
- До трёх окон, новые снизу. При недостатке высоты показывается меньше окон;
  занятый вводом черновик не вытесняется новым уведомлением.
- Нажатие «Открыть» или щелчок по тексту показывает главное окно.
- Electron API не выдаётся странице. Окно sandboxed, IPC проверяет собственное окно,
  главный frame и точный локальный URL; текст ответа не пишется в журналы.

Это опыт с **фиктивной отправкой**. Серверный мост и обработка ошибок настоящей
отправки относятся к Д3. В центре уведомлений Windows этих окон нет; системное
«Не беспокоить» в этой пробной сборке не учитывается (задача Д3).

### Ручная проверка текущего окна

1. Значок у часов → «Проверка уведомлений» → **«Свои окна: Enter / Shift+Enter»** →
   **«1. Сообщение с полем ответа»**.
2. Ввести «первая», нажать Shift+Enter, ввести «вторая»: в поле должны быть две строки,
   подтверждения отправки ещё нет.
3. Нажать Enter: одно «Отправлено…», затем окно закрывается.
4. Повторить опыт и отправить кнопкой «➤»; проверить один ответ.
5. Проверить пункт 2 меню (отложенный показ) при скрытом главном окне, пункты 4 и 6
