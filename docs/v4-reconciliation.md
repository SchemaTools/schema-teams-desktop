# Источник требований и переход на ТЗ v4

28.10.2026. После уточнения руководителя о собственном чате и обновления ветки
обмена обнаружено, что текущая рабочая ветка сохраняла прежнее ТЗ v2.
Актуальный источник находится в `stage/d1`, commit
`cfff98f702a7b07027966f9e8032907ed3468751`:

- [ТЗ v4 от 25.10](https://github.com/SchemaTools/schema-teams-desktop/blob/cfff98f702a7b07027966f9e8032907ed3468751/docs/tz/2026-10-25%20%E2%80%94%20%D0%A2%D0%97%20Schema%20Teams%20Desktop%201.0_v4.md).
- [Сверка серверного API](https://github.com/SchemaTools/schema-teams-desktop/blob/cfff98f702a7b07027966f9e8032907ed3468751/docs/server-api.md).
- [Постановка серверу](https://github.com/SchemaTools/schema-teams-desktop/blob/cfff98f702a7b07027966f9e8032907ed3468751/docs/teams-request.md).

Руководитель сообщил о новом макете. Его получение необходимо для нового
интерфейса; старый макет v1 не принимается за образец собственного чата.

## Существенные изменения

| Область | Прежняя реализация этой ветки | Требование v4 |
|---|---|---|
| Главное окно | весь веб Teams | собственный мессенджер, служебный чат и плагины |
| Авторизация | вход внутри главного веб-окна | отдельное окно входа, постоянный `persist:teams` |
| API | страница через desktop bridge | `session.fetch` в main, CSRF из `/api/auth/me` |
| Realtime | сокет страницы | свой Socket.IO в main с cookie этой сессии |
| Renderer | серверная страница | локальный UI без прямого доступа к сети и секретам |
| Чат | списка/истории в Desktop нет | история, отправка, файлы, реакции, прочтение, поиск |
| Переходы к задачам/объектам | внутри веб-окна | браузер по умолчанию |
| Плагины Revit | за пределами 1.0 | входят в 1.0, отдельный этап |

Базовый чат не зависит от нового desktop-bridge. Уже существующие REST и
Socket.IO сервера сверены на `0.11.2`, `f176f7635a50832b78ba570b56fd9ec5aa2813d4`.
В renderer передаются только проверенные DTO; cookie/CSRF остаются в main,
пароль вводится только на серверной странице входа. Никаких CORS-обходов
или ослабления sandbox/webSecurity не требуется.

Редакция 1 SERVER-CHAT-001 была основана на v2 и предлагала ненужный для v4
мост. Она отменена редакцией 2 в ветке `codex/task-exchange`, commit `0b067fd`.
Редакция 2 касается реакций, признака активных задач на объекте, закрепления
чатов и событий служебного чата. Серверный репозиторий остаётся только для чтения.

## Порядок работ из v4

| Шаг | Состав | Состояние этой ветки относительно v4 |
|---|---|---|
| Д1 | Каркас | существующая основа |
| Д2 | Родные уведомления, допроверка Windows 11 | ручная проверка и согласование клавиатуры остаются |
| Д3 | Вход, main API/Socket.IO, счётчики, тема, меню/уведомления | прежний мост не заменяет этот этап; требуется новая реализация |
| Д4 | Собственный чат и события, файлы, реакции, пути | чат отсутствует; валидатор/worker путей можно использовать повторно |
| Д5 | Обновление плагинов Revit | в этой ветке не реализовано |
| Д6 | Таймер | функции пробной 0.3.0 — заготовка; автопауза/очередь ждут SERVER-D5-001 |
| Д7 | Обновление приложения, настройки, подпись, поддержка, утро | не реализовано полностью |

Нумерация SERVER-D5-001 и названия прежних веток/таблиц сохраняются как
исторические идентификаторы, а не доказательство прохождения новых этапов.
Проверки 232 unit / 47 E2E относятся только к текущей пробной реализации v2.
Они не проверяют собственный чат, новый клиент API, Socket.IO или плагины.

При переносе уведомлений сохраняется прямое указание руководителя из этой
сессии: Enter отправляет, Shift+Enter переносит строку. ТЗ v4 одновременно
указывает родные уведомления и Enter для отправки; прежний опыт Windows 10
показал иную клавиатуру родного поля. Это расхождение нельзя скрыть или молча
вернуть Ctrl+Enter: нужны сверка актуального макета и подтверждение поведения.

Дальнейшая реализация начинается от актуальной `stage/d1` в отдельной ветке;
в неё не переносится архитектура старого моста как готовый Д3. Сохраняются
проверенные утилиты, исправления и ручные результаты без объявления приёмки v4.
