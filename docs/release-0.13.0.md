# Schema Teams Desktop 0.13.0 — заставка и безопасная автопауза

К существующей автопаузе добавлено наблюдение за экранной заставкой Windows.
Main запускает фиксированный read-only helper с `SPI_GETSCREENSAVERRUNNING`;
он не меняет настройки, не запускает `.scr`, не переключает desktop и не читает
реестр. Ответ строго ограничен 128 байтами, запрос — 1,5 секунды. Отсутствие
helper, ошибка, неподдерживаемая платформа или неверный ответ дают `unknown`.

Опрос идёт через две секунды после завершения предыдущего запроса, только
при работающем таймере с автопаузой, незавершённом возврате или сохранённом
состоянии отсутствия. Одновременно работает один helper. Скрытие окна не
останавливает main. Сон отменяет запрос; пробуждение требует нового чтения.
Сохранённое состояние заставки продолжает проверяться и после выхода из
аккаунта или отключения таймерных прав: это право читать ОС, а не писать таймер.

До асинхронного чтения фиксируются Host, пользователь, эпохи, конфигурация,
снимок таймера и поколение наблюдателя. Запоздалое чтение таймера A не ставит
на паузу B. Для свежего `running` используется существующая pause-only очередь
с серверным CAS и прежними ключом, expected и временем при повторе. Локальный
источник — `screensaver`, серверная причина остаётся `lock` по текущему договору.
Серверный код и API не меняются.

Время паузы — момент наблюдения в main по монотонно калиброванным серверным
часам. Это не время запуска заставки и не время последнего ввода. Для нового
события заставки калибровка старше двух минут непригодна. После сна старый
payload таймера не создаёт новую калибровку: нужен ответ сервера. При отсутствии
достоверного времени показывается предупреждение для ручной проверки.

Заставка, блокировка и сон учитываются независимо. `unknown` после `running`
удерживает состояние отсутствия. Возврат фиксируется после снятия всех слоёв;
свежий `stopped`, полученный после разблокировки, честно обозначен как
«Заставка больше не обнаружена». После перезапуска без наблюдённого события
сохраняется формулировка подключения. Записанная граница не меняется из-за
задержки DND, следующего опроса или другого источника возврата.

Popup возвращения ждёт свежего разрешающего наблюдения. Проверки повторяются
после асинхронной политики Windows и перед отметкой показа/кнопкой. Новое
отсутствие отменяет старый показ; прочитанные сообщения и отметки показа не
выдумываются. Продолжение таймера выполняет только явная кнопка с актуальным
CAS. Датчик не запрещает обычные явные действия в окне таймера. Барьер выхода
для обновления из 0.12 сохраняет очередь и не запускает скрытые API-команды.

Новые строгие local-enum читают старые записи без массовой миграции. Неизвестный
формат сохраняется заблокированным. Старый клиент не понимает `screensaver` и
также сохраняет файл, не очищая очередь. Общей очереди start/resume/finish нет.

## Проверка и открытые границы

Итоговый прогон: **1278 unit, 2 skipped и 160 Electron**, все 18 команд успешны,
289 исходных файлов неизменны во время проверки. Каталог приложения сверён:
164 dist-файла, пять helper и полный набор runtime-зависимостей. Независимая
ревизия кода и артефактов завершена. Последующие изменения только этого
документа и статуса плана проверяются отдельно, runtime не меняется.

Реальный упакованный клиент в отдельном профиле на локальном сервере выполнил
шесть read-only запросов: состояние `stopped`, один helper одновременно,
после снятия потребности новых вызовов нет. Получены положительные выборочные
RSS/CPU для всех шести собственных PID, 1–2 отсчёта на процесс. Это не максимум
потребления или лимит суммарной памяти. Путь подтверждён по фиксированному runner,
OS start-time — с допуском три секунды; независимая проверка OS image path
этим замером не заявляется. Таймерные команды на живой сервер не отправлялись.

Подставные `running/unknown/stopped` проверяют код, durable файлы и локальный CAS;
они не являются положительным наблюдением реальной заставки Windows.

Период опроса не гарантирует обнаружение короткого события между запросами.
Задержка main и сна может увеличить интервал. Незапирающая и защищённая заставка,
RDP, Windows 10/11 и работа с Revit требуют ручной приёмки. Сумма памяти прежнего
клиента не является замером нового внешнего helper. Подпись, реальные пакеты
плагинов, NSIS и установка остаются отдельными открытыми проверками. Нерешённое
замечание R02 о фотографии из буфера остаётся в единой Excel-книге.
